## 1. Распиновка A+E1 — ПОЛНОСТЬЮ ЗАКРЫТА

Файл `GPIO_Policy_Matrix_Guide/A+E1_pinout_from_schematic.md` обновлён — все 4 открытых пункта
сняты по ответам автора схемы:

1. **U1TX/U1RX** — выводы 30/31 подтверждены; USART1 vs LPUART1 — решение firmware-уровня, на разводку не влияет.
2. **ALRT (TMP117)** — не используется; датчик контрольный/калибровочный, может отсутствовать в производственной схеме; обработка температуры — программная.
3. **XP2 / UART2 (выводы 12,13)** — сервисный интерфейс, в варианте A был ОСНОВНЫМ каналом связи с ПК по кабелю; может также служить мостом UART↔BLE для отладки и альтернативным путём связи с Qt через адаптер BLE-UART. → Вывод: сервисный протокол должен быть транспорт-независимым. `WKUP1` предположительно — детект подключения кабеля/питания (источник перехода PASSIVE→SERVICE).
4. **PB15 (QRPWR)** — исторический рудимент несостоявшейся схемы плавного пуска питания Flash (резистор-ограничитель → прямое включение через QPWR/вывод 8). От схемы отказались, по факту не используется.

✅ Файл готов как: чек-лист для CubeMX, основа для GPIO Policy Matrix (раздел 9 ТЗ), основа для `power_manager`.

## 2. Прочитана схема LogLSM-B (`Hardware/LogLSMB.jpg`, плата «ЛОГГЕР 950.11»)

Тот же MCU (STM32L433CC). Зафиксированы отличия от A+E1 — **с поправками автора** (важно: первая версия моего анализа была не вполне точна, ниже — исправленная картина):

### Компоненты и изменения:
- **A2 = LSM6DSV320X-MOD** (вместо LSM6DSO-MOD в варианте A) — сенсор с расширенным диапазоном, под событийную регистрацию экстремальных ускорений/ударов.
- **USB добавлен** (USBM/USBP, пины 32/33) — прямая проводная связь с ПК; из-за этого пришлось перетрассировать QSPI (это упоминалось автором ранее).
- **SPI3 добавлен** (NSS3/SCK3/MISO3/MOSI3, пины 38–41) — отдельная высокоскоростная шина, видимо под будущие модули расширения.
- **DAC1 (PA4) и ADC1 (PA5)** выведены на основной разъём XP1 — новые аналоговые каналы наружу.
- **HL1** — светодиодный индикатор состояния (через PA1 + R8).
- **Второй I²C (SCL2/SDA2) и WKUP4** выведены на XP1 — расширены возможности подключения внешней периферии напрямую.

### ПОПРАВКИ автора по системе питания (зафиксировать точно!):

> «пробуждение в нём так же по WKUP1 = supervisor STU просто с сервисного разъёма сразу шло; тревога стабилизатор необходимость из-за 5 вольт USB; ну и коммутатор добавлен чтобы можно было приходить в сервис не вытаскивая батарейку»

- **WKUP1 = supervisor STU** — НЕ новая функция; такой механизм пробуждения уже был в варианте A (там сигнал «тревоги» от стабилизатора шёл прямо с сервисного разъёма). В варианте B он просто интегрирован в более сложную систему питания.
- **DA1 (TPS70933, LDO + супервизор)** появился из-за **USB (5В)** — нужна стабилизация питания под рабочий уровень контроллера.
- **DA2 (TPS2105, PMUX — коммутатор питания)** появился, чтобы можно было **входить в сервисный режим, не вынимая батарею** — аппаратное переключение между батареей (G1, LS14250) и внешним питанием (+VEX/USB) на лету.

### ПОПРАВКА по разъёму XP2 (PLL1.27-05):

> «это тот же разъём, оставлен для совместимости с сервисными кабелями при отладке. Его контакты продублированы на выходах на плату расширения максимального функционала. И раз у нас есть USB — его можно исключить»

- XP2 в варианте B — **тот же** разъём, что в варианте A (НЕ новый/перепроектированный), оставлен ради совместимости с уже существующими сервисными кабелями.
- Контакты продублированы на плате расширения максимальной комплектации.
- Архитектурно избыточен теперь, когда есть USB — кандидат на исключение в будущих ревизиях.

## 3. Итоговый вывод по эволюции A → B

Двигатель эволюции — **появление USB**: оно потянуло за собой необходимость в стабилизаторе питания (5В→рабочий уровень), а тот, в свою очередь — в коммутаторе батарея/внешнее питание (чтобы входить в сервис без разборки устройства). Супервизор напряжения и связанный с ним механизм пробуждения (WKUP1/STU) — это унаследованный из варианта A проверенный узел, не новая разработка. Старый сервисный разъём XP2 сохранён по инерции совместимости, но уже считается потенциально лишним.

Также подтверждена смена IMU на сенсор с расширенным диапазоном (LSM6DSV320X) — прямое отражение «логгерной» специализации платы B под событийную регистрацию экстремальных нагрузок.
