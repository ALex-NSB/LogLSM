# Распиновка платы A+E1 — извлечено из схемы (Hardware/A+E1.jpg, A+E1.pdf)

Источник: реальная схема собранной платы (контроллер LogLSM-A + модуль расширения E1).
Назначение таблицы: (1) фиксация фактической разводки «как есть в железе»; (2) прямой чек-лист
для настройки GPIO в STM32CubeMX «пин → режим/AF → метка».

MCU: **STM32L433CC** (DD2)

---

## 1. Базовые функции платформы (общие для контроллера)

| Пин MCU | Сигнал на схеме | Подключено к | Периферия | Назначение |
|---|---|---|---|---|
| PH0 / PH1 | IM_SCL / IM_SDA | A1 — LSM6DSO-MOD (через R2/R3 4k7) | I²C (программный/аппаратный) | Базовый IMU/акселерометр — шина данных |
| (см. SCL/SDA) | SCL / SDA | A1 — LSM6DSO-MOD | I²C | IMU — шина данных (вторая пара выводов на DD2) |
| WKUP2 | INT1 (от LSM6DSO) | A1 — LSM6DSO-MOD | EXTI / Wakeup | Прерывание от IMU — источник пробуждения |
| OS32I / OS32O | — | BQ1 — кварц 32.768 кГц | RTC | Часовой кварц (база RTC) |
| PA8 (вывод 8) | QPWR | DD1 — P25Q128H (Flash) | QSPI (управление питанием) | **Фактическое питание Flash** — подаётся напрямую (прямое включение, без ступени soft-start) |

## 2. Модуль расширения E1 — добавленная функциональность

### 2.1. BLE-модуль (HLK-B40, DD.1) — связь по UART + управление питанием

| Пин MCU | Сигнал на схеме | Назначение |
|---|---|---|
| U1TX (вывод 30) | U1TX → BLRX модуля | UART передача в BLE (выбор USART1/LPUART1 — на усмотрение прошивки, пины не меняются) |
| U1RX (вывод 31) | U1RX ← BLTX модуля | UART приём от BLE (выбор USART1/LPUART1 — на усмотрение прошивки, пины не меняются) |
| PB12 | B_LIN → LINK | Линия связи/статуса BLE |
| PA5 | B_KEY → KEY | Управляющий сигнал режима BLE |
| PB6 | B_PWON- | Включение питания BLE через силовой ключ VT.1 (BSS215P) |
| PB7 | B_RES | Сброс модуля BLE (RES) |

> Примечание: модуль BLE планировался для бесконтактной передачи данных при отладке.
> Управление питанием через отдельный силовой ключ (VT.1) — прямое отражение принципа
> «периферия включена только когда нужна» (см. ENGINEERING_DECISIONS.md, разд. 3):
> в режимах PASSIVE/WORK BLE должен быть обесточен, включаться только в SERVICE/отладке.

### 2.2. Точный термометр (TMP117AIDRV, DA.1) — I²C, калибровка термодатчиков MCU/LSM

| Пин MCU | Сигнал на схеме | Назначение |
|---|---|---|
| PB13 | SCL2 | I²C2 — линия тактирования к TMP117 |
| PB14 | SDA2 | I²C2 — линия данных к TMP117 |
| PB4 | T_PWR | Управление питанием термодатчика (вкл/выкл по потребности) |
| — | ALRT (DA.1) | Сигнал тревоги/готовности термодатчика (если задействован — уточнить подключение к MCU) |

> Назначение: эталонное измерение температуры для оценки точности встроенных
> термодатчиков MCU и LSM6DSV320X — калибровочный/диагностический узел.

### 2.3. FRAM (FM25V10A-G, DD.2) — SPI, быстрый буфер

| Пин MCU | Сигнал на схеме | Назначение |
|---|---|---|
| PA11 | MISO1 | SPI1 — приём данных от FRAM (SDO) |
| PA12 | MOSI1 | SPI1 — передача данных в FRAM (SDI) |
| PA15 | NSS1 | SPI1 — выбор устройства (CS) |
| PB3 | SCK1 | SPI1 — тактирование |
| PB5 | M_PWR | Управление питанием FRAM/модуля (предположительно) |

## 3. Уточнённые моменты (сверено с автором схемы — закрыто)

- [x] **U1TX/U1RX**: выводы 30 и 31, физическая разводка фиксирована. Выбор периферии (USART1 или LPUART1) — вопрос firmware-уровня, на пины не влияет.
- [x] **ALRT термодатчика TMP117**: не используется (функция тревоги/готовности не задействована). Сам датчик — контрольный/калибровочный узел, в основной (производственной) схеме может отсутствовать; обработка температуры будет программной, а не аппаратной.
- [x] **Служебный разъём XP2 (UART2, выводы 12/13)**: сервисный интерфейс. В варианте A — **основной канал связи с ПК** по кабелю. Дополнительно может выступать как (а) шлюз UART↔BLE для отладки (мост между проводным UART2 и беспроводным BLE-модулем на UART1), и (б) альтернативный путь связи с программой Qt — через внешний адаптер BLE-UART. Вывод: сервисный протокол должен быть транспорт-независимым (поддерживать кабель/мост/беспроводной адаптер как равноправные физические каналы).
  - `WKUP1` (на разъёме XP2), вероятно, связан с обнаружением подключения внешнего питания/кабеля — кандидат на источник перехода `PASSIVE → SERVICE` (см. раздел 8 ТЗ). Требует отдельного подтверждения при необходимости.
- [x] **PB15 (QRPWR)**: исторический рудимент. Изначально задумывался как 1-я ступень схемы плавного пуска питания Flash (включение через резистор для ограничения броска тока заряда конденсатора, затем прямое включение через QPWR/вывод 8 — 2-я ступень). От этой схемы отказались: на практике питание Flash подаётся сразу напрямую через QPWR (вывод 8). **PB15/QRPWR в текущей реализации не задействован.**

## 4. Как использовать эту таблицу

1. **Как чек-лист в CubeMX**: при настройке пина — сверяться со столбцом «Пин MCU» / «Назначение», задавать Label по столбцу «Сигнал на схеме», режим — по столбцу «Периферия».
2. **Как основа для GPIO Policy Matrix** (раздел 9 ТЗ): на базе этой фактической распиновки — дополнить столбцами поведения в режимах RESET/PASSIVE/WORK/SERVICE и источников пробуждения. Особое внимание — пинам управления питанием (B_PWON-, T_PWR, M_PWR, QPWR/QRPWR): для них поведение по режимам критично и должно быть прописано явно.
3. **Как основа для написания `power_manager`**: список пинов управления питанием периферии (BLE, термодатчик, FRAM/Flash) — прямой перечень того, чем эта функция должна управлять при переходах между режимами.
