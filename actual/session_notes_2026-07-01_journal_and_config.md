## Что было сделано

### 1. Запись журнала стенда на диск (`mainwindow.cpp/h`)

- `QFile m_journalFile` — член класса MainWindow (не StendState — QFile не копируется)
- `qint64 m_journalAccMs` — накопленная Стенд-длительность уже записанных циклов (для Общей)
- `stendJournalOpen()` — создаёт файл `Documents/LogLSM_stend_YYYYMMDD_HHMMSS.txt` при «Старт»
- `stendJournalWrite(StendCycleRecord &r)` — пишет блок цикла, флашит, ставит `r.written=true`
- Запись происходит при вытеснении цикла из буфера отображения (4 цикла) и при «Стоп»
- `stendStop()` — дозаписывает все незаписанные циклы и закрывает файл

### 2. Кнопка «Открыть журнал…»

- Добавлена в `stendButtonsLayout` в `mainwindow.ui`, по умолчанию `enabled=false`
- Активируется при `stendJournalOpen()`, кратко деактивируется при новом «Старт»
- `QDesktopServices::openUrl(QUrl::fromLocalFile(...))` — открывает в системном редакторе

### 3. Удалён чекбокс «Не считывать данные с регистратора»

- `chkStendNoRead` убран из `mainwindow.ui` — был артефактом раннего проекта (активный
  опрос после «Стоп»), не реализован и не нужен: данные приходят через CMD_CYCLE_PUSH.

### 4. Формат журнала — колонки с `|`

Причина: Cyrillic labels разной длины + пропорциональный шрифт → «плыли» колонки.
Решение: разделитель ` | ` между колонками, заголовок с левого края.

```
Стенд      | Регистратор
Старт      | 12:41:04  | 12:41:04
Стоп       | 12:41:14  | 12:41:15
Интервал   | 00:00:10  | 00:00:11  | +1 секунда
Общая      | 00:00:20  | 00:09:39  | +559 секунд
Скорость   | 42        | 47        | +11.9%
```

Константы: `W_LBL=10`, `W_DATA=13` — `leftJustified` по символам (Cyrillic = 1 символ).
Рекомендация пользователю: Courier New в UltraEdit (Advanced → Configuration → Display → Fonts).

### 5. Дефолты циклограммы исправлены

Проблема: дефолты в `mainwindow.ui` перебивались хардкодом в `setupStend()` (строки ~1643-1651).
Исправлено в `setupStend()`:

|---|---|---|
| Время работы/простоя сек | 5 | **10** |
| Интервалов (spinChgMin/Max) | 1/1 | **10/10** |
| Скорость мин | 100 | **10** |
| Скорость макс | 600 | **300** |
| Режим | Только + | **N старт/стоп** |

## Блок конфигурации регистратора (план, не реализован)

**Идея:** параметры рабочего режима хранятся в FRAM, загружаются при старте `Service()`,
редактируются через LTP-команды из LOGLSMW.

**Список параметров:**

| Параметр | Текущее (хардкод) | Описание |
|---|---|---|
| `min_cycle_duration_s` | нет | Минимальная длительность цикла — короче выбросить |
| `GYRO_THRESHOLD` | 600 LSB | Мин. угловая скорость для детекта вращения |
| Гистерезис останова | 3 опроса | Подтверждений «нет вращения» подряд перед закрытием цикла (~720 мс) |
| ODR датчика | (заглушка) | Частота опроса IMU (команды SET_ODR не реализованы в прошивке) |
| Режим записи | Режим 1 | Регистратор vs Logger |

**Сознательно НЕ входит:**
- Максимальная скорость — «что можем то и замерим», верхнего лимита нет.
- FS гироскопа — **не статичный параметр**: планируется авто-выбор диапазона
  по измеренной угловой скорости. Отдельная задача, не реализована, не забыть.

**Хранилище конфига и паспорта — внутренний Flash MCU (обязательно, финально):**

| Хранилище | Что хранит | Примечание |
|---|---|---|
| **MCU Flash** (одна страница в конце) | Паспорт + конфиг | Переживает стирание NOR Flash |
| **NOR Flash header** | Только оперативное: указатель записи, счётчик, режим | Конфига нет |
| **Прошивка** (хардкод) | Дефолты — fallback если страница MCU Flash пустая/невалидна | |

**Паспорт:** серийный №, вариант (A/B), дата выпуска.  
**Конфиг:** GYRO_THRESHOLD, min_cycle_duration, гистерезис (noDetectCount), ODR, режим записи (Регистратор/Logger).

**Реализация на STM32L433CC:**
- Выделяем последнюю страницу Flash (2 КБ, адрес `0x0803F800`) под структуру конфига
- Запись через `HAL_FLASH_Unlock` → `HAL_FLASHEx_ErasePageCommand` → `HAL_FLASH_Program` (64-bit)
- Ресурс ~10 000 стираний — более чем достаточно для редких записей
- Валидность: сигнатура (магическое число) в первых байтах структуры

**Поток данных:**
- Старт прошивки → читаем страницу MCU Flash → сигнатура валидна → берём конфиг оттуда
- Сигнатура невалидна (новая плата, первый запуск) → берём хардкодные дефолты
- LOGLSMW (Service mode) → LTP-команды GET/SET_CONFIG → пишет в страницу MCU Flash
- Обычный пользователь → конфиг загружается автоматически, ничего не трогает

**Защита доступа:** запись конфига доступна ТОЛЬКО в Service mode (Сервис → ключ → вкладка
«Настройки»). Обычный пользователь вкладку не видит и команды SET_CONFIG не отправляет.
Это не дополнительная блокировка — уже существующее разделение режимов в LOGLSMW.

**Три уровня хранения (финальная схема):**

| Уровень | Где | Что |
|---|---|---|
| Дефолты | Прошивка (const) | Одинаковы для всех, компилируются |
| Конфиг + паспорт | MCU internal Flash (последняя страница) | Индивидуально, переживает стирание NOR |
| Оперативное состояние | NOR Flash header 0x000000–0x0000FF | Указатель записи, счётчик, режим |
| Данные измерений | NOR Flash 0x000100+ | Записи циклов / фреймы Logger |

Детали (структура, LTP-команды GET/SET_CONFIG, UI) — по ходу реализации.

## Авто-выбор параметров датчика (отдельная критичная задача)

**Статус:** не спроектирована, не реализована. Требует отдельной сессии.

**Почему критично:** неправильная реализация даёт систематическую ошибку во всех данных:
- FS слишком мал → насыщение (clipping) на высоких оборотах, данные обрезаются без предупреждения
- FS слишком велик → грубое разрешение на малых оборотах, низкая точность
- Смена FS меняет цену LSB → GYRO_THRESHOLD в LSB перестаёт соответствовать реальной скорости

**Что нужно авто-выбирать:**
- FS гироскопа (±125 / ±250 / ±500 / ±1000 / ±2000 °/с у LSM6DSO)
- FS акселерометра (±2 / ±4 / ±8 / ±16 g)
- Возможно ODR (баланс точности и энергопотребления)

**Принцип:** устройство начинает с широкого диапазона, следит за максимальными значениями,
при необходимости переключает FS на более узкий (лучшее разрешение) или более широкий
(защита от насыщения). GYRO_THRESHOLD при этом должен пересчитываться автоматически
в соответствии с текущей ценой LSB.

**Архитектура (уточнено 01.07.2026): авто-выбор между прогонами, не в реальном времени.**
- Прогон идёт с фиксированным FS — все данные одного прогона сопоставимы
- `maxRate` уже передаётся в CMD_CYCLE_PUSH — готовая основа для оценки
- LOGLSMW анализирует максимальные значения по итогам прогона: близко к пределу FS → расширить, далеко от предела → сузить для лучшего разрешения
- Перед следующим прогоном — LOGLSMW предлагает/устанавливает оптимальный FS
- FS не меняется внутри цикла никогда — нет проблемы несопоставимости данных

**Связанные зависимости:**
- FS хранится в Flash **один раз на всю пачку** (прогон) как дополнительные биты
  в заголовке пачки — не per-цикл и не per-сэмпл (избыточно). Все записи пачки
  интерпретируются с одним FS. 3 бита на FS гироскопа (5 вариантов у LSM6DSO),
  2 бита на FS акселерометра (4 варианта) — итого 5 бит на заголовок пачки.
