## 2. ГЛАВНАЯ ЗАДАЧА НА СЕССИЮ: активация = журнал во внутренней Flash

### 2.1. Проблема
Признак активации = `ts_activation` в ОЗУ: `static uint32_t s_actts = 0xFFFFFFFF`
(com.c). **Теряется при перезагрузке.** Был на внутр. Flash стр.121 — убрали,
т.к. прерванная запись → битый ECC → hardfault на КАЖДОМ GET_STATS.

### 2.2. Опасность внутренней Flash L4 и обход
ECC на 64-битное слово: ломается при прерывании записи/стирания или повторной
записи слова без стирания → чтение битого слова = hardfault. Обход:
1. Читать из Flash ОДИН раз на старте → кэш `s_actts`; GET_STATS из кэша.
2. Append-only: одно чистое слово в стёртый (0xFF) слот (как журнал 124–127).
3. Писать только под внешним питанием — активация ТОЛЬКО в «Сервис», по кабелю,
   под управляющей программой; «батарейка+вибрация» не наступает.
4. Сигнатура/тип → стёртая страница = «не активировано».

### 2.3. Раскладка (ТРИ РАЗДЕЛЬНЫЕ области) — во ВНУТРЕННЕЙ Flash STM32
⚠ ПОПРАВКА 03.08 к первоначальной таблице: стр.122 УЖЕ занята `DATAFLAG_PAGE`
(флаг «несохранённые», com.c). Журнал активаций положен на **стр.121** — свободную
старую страницу активации. Инженерно так безопаснее: 121 (легаси-риск ECC) читается
ОДИН раз на старте append-only-журналом, а часто читаемый DATAFLAG остаётся на
проверенной 122. Три раздельные области сохранены, семантика команд — как задумано.

| Стр. | Что | Кто стирает |
|---|---|---|
| **121** (`IFLASH_ACT_PAGE`) | Журнал активаций (история «жизней», ts) — РЕАЛИЗОВАНО | «Очистить журналы» (0x27) |
| **122** (`DATAFLAG_PAGE`, com.c) | Флаг «несохранённые данные» | поток стирания NOR (data_flag_clear) |
| **123** (`IFLASH_CFG_PAGE`) | Заводское: паспорт (серийник/вариант/дата), калибровки, конфиг | Только паспорт-команда по «шеф»-паролю |
| **124–127** (`IFLASH_JRN_PAGE0`) | Журнал рестартов | «Сброс WDT» (0x24) + «Очистить журналы» (0x27) |

Журналы (операционка) и заводские данные (личность) — раздельно, разными командами.

### 2.4. Модель «жизней»
- Активация = граница цикла: «Сохранить» (шаг Archive волны) → стирание → новый
  `ts` → новая жизнь. **Деактивации как операции НЕТ.** Журнал накапливает ТОЛЬКО
  активации; «активировано» = есть ≥1 запись, `s_actts` = ts последней.
- Слот: `[0]=EVT_ACTIVATION(0xF3)`, `[2..5]=ts`.
- Состояние = (активировано? по ts) × (несохранённые? по флагу):
  1. Не активировано → политика СПРАШИВАЕТ.
  2. Активировано + флаг снят = «между жизнями» → тишина (ходим по сервису).
  3. Активировано + флаг взведён → ПРИНУДИТЕЛЬНО сохраняем.

### 2.5. Команда «Очистить журналы» (= provision/«деактивация»)
Стереть стр.122 + 124–127 → «не активировано», счётчики 0; **стр.123 не трогать**.
Сервис-only, с подтверждением. Отдельно от «Сброс WDT» (только 124–127).
