# Сессия 30 июня 2026 — Регистратор починен, причина найдена

## Статус: ЗАКРЫТО ✅

---

## Корень проблемы (найден через CubeIDE debug, Call Stack)

**Симптом (из session_notes_2026-06-22):** регистратор молчит, LOGLSMW
получает 12–13 байт без FEND (0xC0), CRC-ошибок 0 — LTP-парсер до пакета
вообще не добирается.

**Стек вызовов при Suspend:**
```
Error_Handler() ← main.c:299
MX_USART2_UART_Init() ← usart.c:74
main() ← main.c:117
```

**Причина:** `MX_USART2_UART_Init()` вызывалась в блоке `USER CODE BEGIN 2`
в main.c, когда тактовая ещё была **4 МГц** (HSI/4, выставленная
`SystemClock_Config()`). При 921600 бод BRR = 4 000 000 / 921 600 ≈ **4**
— ниже аппаратного минимума STM32 (BRR_MIN = 16). `HAL_UART_Init()` возвращал
`HAL_ERROR`, `Error_Handler()` уходил в `__disable_irq() + while(1)`. Устройство
зависало на старте **до** входа в `Service()`, UART не инициализировался.

На 115 200 бод та же ситуация: BRR = 4 000 000 / 115 200 ≈ **35** — выше
минимума, UART стартовал. Именно поэтому в эпоху 115 200 бод проблемы не
было, она появилась именно при переходе на 921 600 (22.06.2026).

---

## Исправление

В `Firmware/LOGLSMA/Core/Src/main.c`, блок `USER CODE BEGIN SysInit`
(между `SystemClock_Config()` и `MX_GPIO_Init()`):

```c
  /* USER CODE BEGIN SysInit */
  ServiceClock_Config();   /* HCLK = 16 МГц ДО инициализации периферии */
  /* USER CODE END SysInit */
```

После этого порядок исполнения:
1. `SystemClock_Config()` → 4 МГц (HSI/4)
2. `ServiceClock_Config()` → 16 МГц (HSI, без делителя)  ← новая строка
3. `MX_USART2_UART_Init()` → BRR = 16 000 000 / 921 600 ≈ **17** → OK

`ServiceClock_Config()` уже была определена в `USER CODE BEGIN 4` и
объявлена в `USER CODE BEGIN PFP` (forward declaration добавлена в этой же
сессии — см. summary прошлой сессии).

## Попутное — стенд (com_interr.c заменён симулятором)

**Важно:** в ходе диагностики (предыдущие сессии) `Stend/Stend LOGLSM/Core/Src/com_interr.c`
был **заменён** симулятором LOGLSMA (отвечает на 0x8D, эмулирует WHO_AM_I/
GET_STATS/температуры/FLASH_READ — всё фиктивное). Стенд как ретранслятор
(relay 0x8D → USART3) и контроллер шагового двигателя (0x8C → StepDriver)
**не работает** с этим файлом.

Для восстановления стенда нужно вернуть `com_interr.c` к версии с DMA-приёмом
обоих UART (USART2 к ПК + USART3 к регистратору, relay по ADDR, StepDriver
по cmd 0x04/0x05/0x06). Рабочая версия сохранена в git (22.06.2026).
