## Главные изменения за сессию (LOGLSMW, вкладка «Тест памяти»)

### Переименования/структура панелей
- Рамка **«Образ»** → **«Данные»**.
- Строка **«Размер»** → **«Занято»**: Задать = занято страниц (страницы, десятичное,
  **красный** `#C03030`), Факт = осталось свободно страниц (**зелёный** `#1D7A4C`).
  Источник — `m_firstFreePage`, обновляется хелпером `updateOccupiedLabel()`.
- Строка **«Загрузка»** → **«Адрес»**: колонка «Задать» убрана целиком, остался
  только **«Факт»** (растянут на обе колонки, colspan=2, 192px) — байтовый адрес
  операции, формат `0x` + 8 hex-знаков (страница×256).
- Рамка «Проверка»: заголовок «Проверка» — в одной строке с «Задать»/«Факт»
  (не отдельным заголовком сверху).
- «Термотест»: убран `spinTPasses` (страниц-на-точку) — теперь берётся из
  «Страниц»/Задать (Проверка, `spinMemPages`).

### Нумерация страниц (важно!)
- **Адрес** (Данные) — 0-based, шестнадцатеричный (как принято для адресов).
- **Старт/Страниц** (Проверка) — **1-based** на экране (порядковый номер),
  десятичный. Служебная страница (внутренний индекс 0) отображается как «1»,
  первая обычная страница (`kLogStartPage`=1 внутри) — как «2». Внутри кода
  везде идёт `value() - 1` при чтении спинбокса и `+ 1` при записи/выводе.
  **Это критично помнить при любых будущих правках, трогающих номера страниц.**

### Термотест / Образ / Проверка — общий принцип
- Термотест и «Образ RG/LOG» теперь **всегда** стартуют с первой свободной
  страницы (`m_firstFreePage`), без автостирания — данные накапливаются.
- «Старт»/«Страниц» (Проверка) теперь **общее** отображение хода для ВСЕХ
  операций (обычная «Запись»/«Чтение», термотест, «Образ») — Задать/Факт
  живо обновляются по ходу.
- Произвольный «Старт» (не с границы) доступен **только** через обычную
  «Запись»/«Чтение» — с предупреждением, если создаёт «дыру» (страница дальше
  `m_firstFreePage`, бинарный поиск может дать неверный результат на дырах).
- Предупреждение при записи на служебную страницу (внутренний индекс 0,
  отображается как «Старт=1») — тоже есть, подтверждение через диалог.
  При подтверждении ставится флаг `m_page0Written`, который учитывается в
  `updateOccupiedLabel()` (+1 к занятости), сбрасывается при полном стирании чипа.

### Порог ошибок (новое поле)
- «Ошибок»/Задать — теперь редактируемый спин-бокс `spinMaxErrors`
  (заменил бывший `lblCurStep`). Диапазон: `-1` (спец.значение, отображается
  знаком **`∞`**) = не останавливаться, считать всё. `0` = нулевая терпимость
  (стоп на первой же ошибке). `N>0` = стоп при достижении N ошибок.
  Применяется одинаково к «Запись» (через контрольное чтение, см. ниже) и
  к обычному «Чтение».

### Верификация записи (новая функциональность)
- «Запись» теперь после каждой страницы сразу шлёт контрольное чтение
  (новый тег `TagWriteVerify = 12`) и сравнивает с ожидаемым байтом.
  При накоплении ошибок ≥ порога (`spinMaxErrors`) — останов всей серии
  (`m_dev->clearQueue()`).
- «Байт»/Факт (`lblCurByte`) — убрано домысливание «…» при неоднородной
  странице (убрано поле `lastReadUniform` целиком) — показывается только
  реально прочитанное значение.

### SPI режим (реальная команда в прошивке!)
- Выпадающий список «SPI» (в «Проверка») — теперь реально управляет чипом
  через LTP-команду **`0x2B`** (`FLASH_SET_SPI_MODE`, только для ручной
  проверки в «Сервисе»): `0`=SPI (standart_mode), `1`=SPIx4 (quadspi_mode).
  SPIx2 (dual_mode) сознательно не реализован (в enum есть, в драйвере — нет).
  «МГц» (16/8/4/2/1) — **только визуальный**, команды в прошивке нет.
- **Критичный фикс в прошивке**: `cmdFlashSetSpiModeHandler` теперь вызывает
  `P25Qx_Reset()` перед каждым переключением режима — иначе софт и чип могли
  разойтись в реальном протоколе (SPI обрывалось на середине, SPIx4 давало
  сплошной мусор 0xDD). См. `p25q128.h`/`p25q128.c`.
- Ещё один фикс в прошивке: `P25Qx_QPI_EraseSector` и `P25Qx_QPI_ReadID`
  раньше жёстко слали 4 линии без проверки `handle->mode` — исправлено по
  образцу остальных функций драйвера.

## Найденные и исправленные баги (архитектурные, важно для будущего)

1. **`memTestDump()` переиспользует `m_test.*`** — любой автоматический показ
   гекс-дампа (после записи/чтения/образа/входа на вкладку/стирания) временно
   подменяет состояние теста (`pageStart/pageTotal/pagesDone/errTotal`) для
   СВОЕГО прогона чтения (ограничен `kAutoDumpMaxPages=64`). Если не защитить —
   панель «Проверка» показывает мусор от дампа вместо настоящего результата
   теста. Решение — **два флага**:
   - `m_silentDump` — для полностью фоновых/незначимых дампов: по факту
     завершения панель просто блэнкается (`pageTotal=0`).
   - `m_restoreTestAfterDump` + `m_savedTestForDump` — для дампов, где
     результат теста ДОЛЖЕН остаться видимым (после «Запись»/«Чтение»/
     «Образ»): сохраняем `m_test` ДО вызова `memTestDump()`, восстанавливаем
     ТОЛЬКО когда дамп реально (асинхронно!) завершится — в общем месте
     обработки (там же, где проверяется `m_silentDump`).
   - **ВАЖНО**: нельзя восстанавливать/сравнивать состояние сразу после
     вызова `memTestDump()` — это АСИНХРОННАЯ операция (шлёт FLASH_READ,
     ждёт ответ). Синхронное восстановление сразу после вызова один раз уже
     привело к крашу приложения при заходе на вкладку «Тест памяти».
   - Есть **минимум 4 места** вызова `memTestDump()` — при добавлении новых
     операций проверять, не нужна ли такая же защита.

2. **Бинарный поиск (`flashBinSearchStart`) предполагает Flash заполненной
   строго подряд от стр.1** — если стереть/записать не на границе (дыра
   посреди свободного места), результат может быть неверным. Осознанное
   решение: не менять на линейное сканирование (медленно, ситуация
   искусственная), только предупреждать пользователя перед такой записью.

3. **Постранично vs побайтово**: минимальный блок программирования флеша —
   **страница = 256 байт** (устоявшийся термин в проекте, НЕ «слово» — то
   означает 2 байта в электронике и путает).

## Протокол работы (форматирование архивов)
- Оба архива (`W_.../A_...`) собираются и выкладываются **только по прямой
  просьбе Ed** — не после каждой правки.
- Каждый архив — **полный набор всех изменённых файлов**, никогда не частями.
- W собирается с внутренним путём `LOGLSMW/...` (для распаковки прямо в
  корень проекта одной командой) — то же самое давно принято для A
  (`LOGLSMA/App/Src/...`, `LOGLSMA/App/Inc/...`).
- Версия увеличивается при **каждой** новой отправке архива, даже если это
  просто пересборка без содержательных изменений (было прямое указание Ed).
