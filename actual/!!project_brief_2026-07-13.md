## 1. Что это за прибор

LogLSM — автономный инерциальный логгер (регистратор) на микроконтроллере
STM32L433CC. Устанавливается на ось колеса. Питается от батарейки (LS14250,
3.6 В), поэтому главное требование — минимальное энергопотребление и «не уснуть
навсегда» в поле. Прибор фиксирует **вращение** (обороты) и **вибрацию**
(ударные нагрузки), пишет их в NOR Flash (P25Q128, 16 МБ). Данные выгружаются
через сервисный UART-кабель или (в будущем варианте B) через USB-C.

Датчик движения — IMU LSM6DSO (акселерометр + гироскоп). Есть также датчик
температуры TMP117 и энергонезависимая память FRAM.

## 2. Два аппаратных варианта

**Вариант A (LOGLSMA + модуль MA00)** — СОБРАН, на стенде, отлаживается.
IMU LSM6DSO (±16g, WHO_AM_I=0x6C). Сервисный UART. Это основной рабочий вариант
на сегодня.

**Вариант B (LOGLSMB + модуль MB00)** — запланирован, не собран. IMU
LSM6DSV320X с ДВУМЯ акселерометрами (low-g + high-g ±320g), USB-C, FRAM, TMP117.
Формат данных уже заложен так, чтобы вариант B лёг в него без переделки.

Имя устройства в дизайнерском написании: **LogLSMa** (финальная «a» строчная —
служит разделителем перед модулями, напр. `LogLSMaE00`).

## 3. Как работает регистратор (рабочий цикл)

Три уровня энергопотребления, автомат переключается сам по движению:

- **Глубокий сон** (Stop2, ~7 мкА): МК спит, слушает только акселерометр
  (Wake-Up по движению, низкая частота опроса датчика). Опроса в покое нет.
- **Проверка** (по движению просыпается): коротко включает дорогой гироскоп,
  смотрит — реальное вращение или случайная тряска. Нет вращения долго —
  обратно в глубокий сон.
- **Вращение**: считает обороты и вибрацию за цикл, по окончании пишет запись
  во Flash (и, если подключён кабель, дублирует по связи на ПК).

Ключевые принципы: старт цикла = момент пробуждения (нет «мёртвого времени»);
дорогой гироскоп включается редко (троттлинг с эскалацией), дешёвый
акселерометр слушается всегда. Термины режимов: **Пассивный / Активный /
Сервисный** (+ переходное «между землёй и небом»).

Сон реализован на **Stop2** (сохраняется ОЗУ), а не Standby. Именно выбор Stop2
открывает возможность двухуровневой защиты живучести (см. §6).

## 4. Что пишется в запись (формат v2, 48 байт)

Одна запись на цикл вращения, до 5 записей на страницу Flash. Поля: метка
времени старта, длительность цикла, накопленная наработка, средние и пиковые
обороты, **вибрация — два канала, каждый пик + RMS**, температура, версия
формата, признак варианта, CRC.

Про два канала вибрации (важно, формат ЕДИНЫЙ для A и B, оба канала всегда
заполнены):
- на **варианте A** оба канала = ОДИН акселерометр, посчитанный двумя разными
  способами (канал 1 — полнополосный уровень вибрации; канал 2 — ВЧ/ударный,
  импульсность/jerk);
- на **варианте B** те же два канала = два ФИЗИЧЕСКИХ акселерометра (low-g /
  high-g ±320g).

Пик = худший удар, RMS = средняя тяжесть. Второй режим Flash — «Logger»:
сырой поток отсчётов IMU кадрами по 256 байт (вся обработка потом на ПК).

## 5. Связь и инструменты

Протокол — **LTP** (LogLSM Transport Protocol, эволюция WAKE): кадры с адресом,
командой, CRC16. Адресация: стенд 0x8C, регистратор 0x8D, удалённый по BLE 0x8E.
Сервисный UART — 921600 бод (DMA-приём).

**Стенд** — Nucleo-L476 крутит шаговый двигатель по циклограмме (задаёт обороты),
ретранслирует пакеты регистратору. ПК-приложение **LOGLSMW** (Qt5) управляет
стендом, ведёт единый журнал испытания на общей шкале времени, сверяет
«стенд задал ↔ регистратор измерил». Вкладки: Стенд, Мониторинг, Тест памяти,
Данные, Калибровка (заглушка).

Разделение «Тест» vs «Работа»: **Тест** — та же логика цикла, но БЕЗ сна
(прибор всё время на связи, для отладки); **Работа** — реальный автономный
режим со сном.

**Индикатор версии прошивки** (инструмент контроля): регистратор сообщает свою
версию (время сборки ГГ.ММ.ДД ЧЧ:ММ) + имя, LOGLSMW показывает на вкладке
«Данные». Версия ставится вручную автором кода при каждой правке прошивки.
Инвариант: версию меняет только автор; любое расхождение = аномалия (прошит
старый образ), это стоп-сигнал, а не норма.

## 6. Живучесть (защита «не уснуть навсегда») — спроектирована, не в коде

Двухуровневый сторож (возможен именно благодаря Stop2):
1. **IWDG** — независимый сторожевой таймер, заморожен во сне, бьёт сбросом
   только по зависанию БОДРОГО кода.
2. **RTC-backstop (~1 ч)** — редкое пробуждение по часам, резюмит сон БЕЗ
   сброса (ОЗУ цело), вытаскивает прибор, если единственный источник
   пробуждения (движение) «умер».

Оба спроектированы (документ `wake_architecture_v1.md`), в прошивке пока НЕ
реализованы — есть только сторона распознавания сброса.

## 7. Калибровка — принцип

Вся калибровочная аппаратура — на СТЕНДЕ; в приборе только хранение и применение
коэффициентов. Время: RTC-калибровка от GPS-PPS (постоянный член) + температурная
поправка по TMP117; посев абсолютного времени по GPS UTC. Скорость: пока
одноточечный коэффициент, план — многоточечная таблица + температурная поправка.
Документ `calibration_spec_v1.md`. В коде почти ничего — план.

## 8. Статус: сделано / осталось

**Сделано и подтверждено на железе:**
- Вариант A собран, регистратор отвечает, пишет записи v2 во Flash.
- Трёхуровневый автомат рабочего цикла (сон/проверка/вращение) на Stop2;
  интервалы стабильны, ток снижен.
- Гироскоп-троттлинг с эскалацией; ODR глубокого сна ~26 Гц (~7 мкА).
- Формат записи v2 (48 байт) с полями под 2 канала вибрации (пик+RMS).
- Стенд крутит по циклограмме, LOGLSMW ведёт журнал и сверку, мониторинг
  живого IMU, тест/образ памяти, двоичный поиск границ Flash.
- Индикатор версии прошивки + имя `LogLSMa` из контроллера.

**Осталось довести (по убыванию важности):**

   (математика доказана на «Мониторинге», но прошлый код вешал прибор; сейчас
   прошит урезанный вариант без вибрации). Плюс доопределить «другую математику»
   канала 2 для варианта A.
2. **Двухуровневый сторож** — завести IWDG (заморозка в Stop) + часовой
   RTC-backstop в ветку глубокого сна. Критично для поля.
3. **Калибровка скорости** — многоточечная таблица + вкладка «Калибровка»;
   RTC-калибровка времени от GPS-PPS, посев абс. времени.
4. **Паспорт устройства** — серийник/вариант/дата во внутренней Flash STM32;
   блокировка стирания для инициализированного прибора.
5. **Logger-режим** — код полной шкалы на кадр, поиск границ цикла в потоке,
   раскладка CSV. Не спроектирован.
6. **UI-мелочь** — индикатор состояния памяти, отображение FRAM в LOGLSMW.

Пункты 1 и 2 — «мясо» автономного регистратора; остальное — доводка и сервис.

## 9. Мини-глоссарий

- **Регистратор** — сам прибор LogLSM (вариант A = LOGLSMA).
- **Стенд** — испытательная установка (Nucleo + шаговый двигатель).
- **LOGLSMW** — ПК-приложение (Qt5) для управления и анализа.
- **LTP** — протокол связи.
- **Запись v2** — 48-байтная запись цикла вращения.
- **Тест / Работа** — режимы без сна / со сном.
- **Пассивный / Активный / Сервисный** — режимы энергопотребления.
- **Stop2 / Standby** — режимы сна STM32 (используется Stop2).
- **IWDG / RTC-backstop** — два уровня защиты живучести (спроектированы).
