## 1. Главный принцип: ФЛАГ = состояние, ЖУРНАЛ = записи. Это РАЗНОЕ.

- **Флаг** — текущее состояние прибора (взведён/нет), основной признак.
- **Журнал** — история событий (ts начала/конца жизни, счётчики). Не дубль флага.
- Их **НЕЛЬЗЯ смешивать**. «Очистить журналы» (0x27) чистит ТОЛЬКО записи
  журнала — состояние/флаги НЕ меняет. Состояние активации берётся из ФЛАГА
  (NOR offset0), а НЕ из журнала.
- Индикаторы состояния должны периодически обновляться (фоновый опрос дашборда),
  иначе «загрузишь, а они где-то там» — показывают устаревшее.

## 2. Флаги состояния — во внешнем NOR, служебная страница 0

Раньше флаг «несохранённые данные» жил во ВНУТРЕННЕЙ Flash STM32 стр.122
(DATAFLAG). **Убран совсем** — на батарее опасен (erase+program+ECC на 64-битное
слово → битый ECC → hardfault). Флаги переехали во ВНЕШНИЙ NOR.

**Хранилище:** служебная **страница 0** внешнего NOR (P25Q128). Флаги — ЦЕЛЫМИ
БАЙТАМИ подряд (так визуально проще контролировать в хекс-дампе).

**Нумерация (важно, договорились):** «байт N» находится по offset (N−1).
То есть **1-й байт = offset 0**.

| Смысл | Индекс (Data.h) | offset в стр.0 |
|---|---|---|
| **активирован** | `NOR_FLAG_ACTIVATED = 0` | 0 |
| **данные_есть** | `NOR_FLAG_DATA = 1` | 1 |
| **сохранение выполнено** (= конец жизни) | `NOR_FLAG_SAVED = 2` | 2 |

**Кодировка байта:** база `0x55` (узор теста) или `0xFF`; **взведён = `0x00`**.
Взведение = program битов 1→0 БЕЗ стирания (безопасно на батарее). Флаги
**set-only**: по отдельности не сбрасываются.

**Сброс ВСЕХ флагов = стирание данных.** Стр.0 лежит в одном 4КБ-секторе с
данными (стр.1..15); команда стирания данных (0x2A) зануляет бэкап стр.0 →
флаги обнуляются вместе с данными. Активацию (журнал стр.121) стирание данных
НЕ трогает.

**API:** `data_norflag_get(idx)` / `data_norflag_set(idx)` в `Data.c` (QSPI).

## 3. Кто какой флаг взводит

| Событие | Где | Что делает |
|---|---|---|
| **Активация** (0x30 action 1) | Сервис/кабель | взводит offset0 + пишет НАЧАЛО (`EVT_ACTIVATION`) ts в стр.121 |
| **Запись цикла** | Батарея, `SaveParamOnEEPROM` | взводит offset1 «данные_есть» (один program, безопасно) |
| **Сохранение/снятие** (0x30 action 3) | Сервис | взводит offset2 + пишет КОНЕЦ (`EVT_ACT_END`) ts в стр.121 |
| (0x30 action 2) | — | взводит только offset2 (SAVED) |
| (0x30 action 4) | — | взводит только offset1 (DATA) |

**Ответ 0x30 = МАСКА:** `0x01` активирован / `0x02` данные_есть / `0x04` сохранено.
W разбирает в `m_deviceActivated` / `m_dataPresent` / `m_dataSaved`;
`m_dataFlagSet = m_dataPresent && !m_dataSaved` (есть несохранённые данные).

## 4. Состояние / режимы — трёхпозиционная надпись «Активация»

Строится по флагам offset0 и offset2:

| offset0 | offset2 | Надпись (оператор) |
|---|---|---|
| чист | — | **не активирован** |
| взведён | чист | **активирован** + дата (в две строки: «активирован» \n дата) |
| взведён | взведён | **деактивирован** (конец жизни, сохранение выполнено) |

- Термин **«между жизнями» — НЕПРАВИЛЬНЫЙ** для оператора. У оператора третье
  состояние = «деактивирован». «Между жизнями» — только внутреннее понятие
  сервиса, в UI оператора его нет.
- «Активирован» ВСЕГДА с датой (ts начала жизни).

## 5. Сегмент 0 «Сохранить» (лента активации)

Кнопка отражает ТОЛЬКО состояние сохранения, **НЕ содержимое памяти**
(содержимое памяти — это кнопка «Память», отдельно).

- `m_dataFlagSet` (есть несохранённые данные) → **красный** «Сохранить» (Idle).
- иначе → **зелёный** «Сохранено», если после волны (`m_saveWasWave`);
  **жёлтый**, если после одиночного срабатывания.

**Цветовое соглашение (общее):** зелёный после волны, жёлтый после одиночного
срабатывания, красный когда надо (есть несохранённое).

## 6. Журнал активаций (стр.121) = интервалы «жизней»

- `EVT_ACTIVATION` (0xF3) — начало жизни (при активации).
- `EVT_ACT_END` (0xF4) — конец жизни (при сохранении/снятии).
- Пара НАЧАЛО…КОНЕЦ = один интервал жизни.
- «Активирован сейчас» = ФЛАГ offset0 (НЕ «последнее событие журнала»).
- В слот КОНЦА пишутся счётчики перезапусков на момент события:
  `slot[6]` = счётчик по таймеру (IWDG/RTC), `slot[7]` = по питанию (POR/BOR,
  клип 255). Отсюда «перезапусков за жизнь».
- `iflash_activation_events()` → types/ts/restarts. LTP **0x2E** отдаёт события;
  W рисует историю в ДВЕ строки: «начало → конец» (или «→ (идёт)» для открытой).

---

## 7. Счётчики перезапусков

- Счётчик работает ВСЕГДА: инкремент при watchdog/power-рестарте, сброс — «Сброс
  WDT» (0x24). Отдельная механика, независимая от активации.
- В журнал попадает только РЕЗУЛЬТАТ (значение счётчика) в момент события
  активации/конца. Пока прибор НЕ активен — новые тестовые перезапуски в истории
  не отображаются и не накапливаются как «за жизнь».
- Волна активации своим шагом «Сброс WDT» естественно обнуляет счётчик на старте
  новой жизни — отдельного гейта на сброс при активации НЕ нужно.

---

## 8. Политика сохранения `dataSaveFlow()` (§3.2)

Все манипуляции активация/деактивация — на СТЕНДЕ (сервис/кабель). Ранних/
батарейных случаев тут нет.

- **сохранено** → вход в сервис БЕЗ запроса.
- **не сохранено + активирован** → подтверждение «Сохранить дамп? Да/Нет»
  (не плодить файлы).
- **не активирован** → диалог [в файл] / [отметить без файла] / [отмена].

- **`Wait_Busy` (p25q128.c) — ТАЙМАУТ 1 с.** Раньше при обесточенном флеше (после
  сна) крутился вечно → вешал ВЕСЬ МК (таймаут 0x1b на все команды, спасал только
  сброс питания). Теперь флеш-операция не может подвесить МК навсегда — прибор

  — иначе после зависания прибора гейт «Сначала остановите операцию» блокировал
  вход в сервис.
