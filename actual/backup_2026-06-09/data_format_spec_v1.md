# LogLSM — Спецификация форматов хранения данных v1.0

Статус: **ФИНАЛЬНЫЙ** (согласован 08–09 июня 2026)  
Применимость: оба варианта контроллера (A и B), все варианты плат расширения.

---

## Общая архитектура хранения

Flash (P25Q128H, 16 МБ NOR) используется в режиме **последовательной записи в предварительно стёртые ячейки**. Стирание производится только в сервисном режиме при подключении к ПК. В рабочем и пассивном режимах — только запись в чистые (0xFF) адреса.

Минимальный физический блок записи в Flash — **256 байт** (одна страница NOR Flash).

---

## Режим 1 — Регистратор цикла вращения

### Идеология
Формирует **один нормированный итоговый результат за рабочий цикл** (начало–конец вращения). Записей мало (раз в цикл), объём данных некритичен, расширенная разрядность оправдана.

### Структура записи (30 байт)

| Поле | Размер | Формат | Примечание |
|---|---|---|---|
| timestamp_start | 32 бита | uint32 | Unix timestamp начала цикла |
| timestamp_end | 32 бита | uint32 | Unix timestamp конца цикла |
| duration | 32 бита | uint32 | Длительность цикла (секунды или мс) |
| MAX_vibration | 32 бита | float32 | Максимальная вибрация за цикл |
| MAX_RPM | 32 бита | float32 | Максимальная скорость вращения за цикл |
| temperature | 32 бита | float32 | Температура (°C) |
| battery_voltage | 32 бита | float32 | Напряжение батареи (В) |
| CRC + флаг | 16 бит | uint16 | CRC записи + служебный флаг |

**Итого: 7 × 4 + 2 = 30 байт.**

Единая разрядность 32 бита для всех полей — не ради точности, а ради **унификации структуры**: единый код сериализации через float32/uint32, выравнивание по 4 байта, отсутствие особых случаев в коде. Экономия 4 байт/запись (~0.0025% от 16 МБ Flash) признана пренебрежимой.

### Архитектура записи — схема «stub + дозапись»

**Схема обязательна** — не только как страховка от сбоя питания, но и для штатного завершения цикла (необходимо уйти в пассив немедленно после конца цикла, без риска потери данных в RAM).

**1. Начало рабочего цикла:**
```
Flash[write_ptr] ← { timestamp_start | 0xFF×26 | 0xFF×2 }  // 30 байт
stub_addr = write_ptr
write_ptr += 30
```

**2. Во время цикла:** MAX_vibration, MAX_RPM, temperature, voltage — накапливаются только в RAM.

**3. Конец цикла (штатный):**
```
Flash[stub_addr + 4]  ← timestamp_end      // NOR: запись в 0xFF-байты разрешена
Flash[stub_addr + 8]  ← duration
Flash[stub_addr + 12] ← MAX_vibration
Flash[stub_addr + 16] ← MAX_RPM
Flash[stub_addr + 20] ← temperature
Flash[stub_addr + 24] ← battery_voltage
Flash[stub_addr + 28] ← CRC               // CRC пишется последним — финальная «печать»
```

**4. Обнаружение незавершённых записей при старте:**  
Запись с `CRC == 0xFFFF` → цикл был начат, не завершён → отбрасывается или маркируется как «прерванный цикл». Минимум: `timestamp_start` сохранён на Flash.

## Режим 2 — Logger (потоковая регистрация)

### Идеология
Формирует **непрерывный поток сырых сэмплов** в течение рабочего цикла. Записей много (сотни Гц), компактность критична. Используется схема **block floating point** (общий масштаб на блок сэмплов).

### Структура блока

```
[ HEADER (16 бит) | DATA[0] (16 бит) | DATA[1] (16 бит) | ... | DATA[count-1] (16 бит) ]
```

#### Заголовочное слово (16 бит)

| Биты | Поле | Описание |
|---|---|---|
| [15:12] | SCALE | 4 бита — показатель степени масштаба (0..15) |
| [11:8] | FLAGS | 4 бита — флаги блока (режим, ODR-код и т.п.) |
| [7:0] | COUNT | Фактическое количество сэмплов в блоке (1..255) |

#### Слова данных (16 бит, знаковые)
Знаковая мантисса в формате two's complement. Физическое значение:

```
physical_value = DATA[i] × (2 ^ SCALE) × LSB_датчика
```

### Параметр N — размер буфера масштабирования

**N — параметр прошивки, не параметр формата.** Определяет, сколько сэмплов накапливается в RAM перед записью одного блока. Влияет на **точность выбора SCALE** (качество масштабирования):

- Большее N → пик ищется по большей выборке → SCALE точнее, меньше «дребезга» масштаба между блоками.
- N=1 → SCALE выбирается по одному сэмплу → валидный результат, максимальные накладные расходы заголовка.
- Типовые значения: N=16 или N=32. Выбор — настройка прошивки без влияния на формат файла.

### Алгоритм автоматического выбора масштаба

1. Накопить N сэмплов по всем осям в RAM-буфере.
2. Найти пиковое значение по модулю: `peak = max(|sample|)` по всем сэмплам и всем осям.
3. Вычислить SCALE:
   ```
   SCALE = max(0, ceil(log2(peak / MANTISSA_MAX)))
   где MANTISSA_MAX = 32767 (0x7FFF)
   ```
4. Закодировать все сэмпли блока: `encoded = sample >> SCALE`.
5. Записать заголовок (SCALE, FLAGS, COUNT=N) и данные в Flash.
6. **Гистерезис:** SCALE повышается немедленно при угрозе насыщения; понижается только после нескольких блоков подряд с большим запасом — для предотвращения «дребезга» масштаба.
7. Переполнение внутри блока невозможно — масштаб выбирается по итоговому пику всего блока (буферизация гарантирует это).

### Архитектура записи

- Запись в Flash по 256-байтным страницам — **непрерывно в течение всего цикла** по мере заполнения буфера.
- **В конце рабочего цикла:** если в RAM остались накопленные, но ещё не записанные сэмпли (< N), они записываются как отдельный блок с COUNT = фактическое количество сэмплов.
- Таким образом потери данных при штатном завершении цикла нет.

## Обоснование надёжности

| Сценарий | Регистратор | Logger |
|---|---|---|
| Штатное завершение цикла | ✅ Stub на Flash с начала цикла, дозапись полей при завершении | ✅ Последний неполный блок пишется с COUNT < N |
| Сбой питания / reset во время цикла | ✅ CRC=0xFF → запись помечается как неполная, timestamp_start сохранён | ✅ Последний записанный блок уже на Flash, неполный буфер RAM теряется (некритично) |
| Дребезг контактов батареи (<10 мс) | ✅ Компенсируется буферным конденсатором (полимерный танталум 470 мкФ + резистор 3.3 Ом) | ✅ Аналогично |
