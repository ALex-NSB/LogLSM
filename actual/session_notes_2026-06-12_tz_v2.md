## Решения дня

- **Алгоритм при подключении** (ТЗ §2.6): индикатор → время → правая колонка →
  шапка «Активного времени» (GET_STATS) → нормировка X → считывание автоархива,
  графики заполняются слева направо = индикатор прогресса (отдельный прогрессбар
  не нужен).
- **Число записей НЕ хранится**: двоичный поиск первой пустой записи
  (30 байт = 0xFF, граница записей от 0x000100), ~24 чтения — мгновенно.
- **Максимумы НЕ хранятся в firmware**: приложение вычисляет при считывании,
  шкала Y автокалибруется живьём (эффектно, лишних сохранений нет).
- **Термин**: максимумы — «за время измерения» (не «за все периоды»).
- **Активация**: при очистке памяти графики стираются синхронно (визуализация);
  после активации — зелёная шкала + дата/время активации.
- **Время активации хранится в САМОМ регистраторе** (заголовок Flash, пишется
  при 0x1D, живёт до следующей активации) → оценка остатка батарейки LS14250
  на любом ПК. Копия в журнале/архиве вторична.
- **MAX_RPM = только гироскоп** по оси вращения (об/мин = dps/6); диапазона
  333 (A) / 666 (B) об/мин достаточно. Акселерометрный метод (период вращения g)
  отвергнут: большие вибрации — дорога с кочками, не ЖД.
- **MAX_vibration = пик ВЧ-составляющей** |a| за цикл (минус гравитация +
  центробежная); пересмотреть можно позже.
- **GET_STATS = 0x1E**, payload 22 байта (ТЗ §7.1): наработка, первый/последний
  цикл, время активации, перезапуски (таймер/питание), режим, версия.
  Счётчики перезапусков в NOR — унарно (гашение бит, без стирания).

## Память Flash — варианты чипа и стирание (16.06)

- **Встречается PY25Q128HA** (суффикс «A»): ХУДШИЕ тайминги — огромное время
  стирания чипа, и **НЕТ стирания страницы/сектора** (только полное стирание).
- Прошивка: `P25Qx_QPI_EraseChip` — **неблокирующая** (`Wait_Busy` закомментирован):
  команда выдана, ACK приходит мгновенно, чип стирается в фоне. `cmdFlashGetState`
  (0x09) возвращает бит **WIP** (занятость). `P25Qx_QPI_ErasePage` — блокирующая
  (`Wait_Busy`), на HA-варианте может не поддерживаться.
- **Стирание чипа в LOGLSMW = опрос WIP** (не фикс. таймаут!): послать 0x05 →
  мгновенный ACK → опрашивать 0x09 пока WIP=0, показывая прошедшее время.
  Корректно для любого варианта, включая медленную HA. «Стереть стр.» на HA
  может быть недоступно — обработать ошибку/таймаут спокойно.

## Управление питанием — сторож от «вечного сна» (16.06, на будущее)

В firmware СЕЙЧАС НЕТ ни Stop2, ни RTC-будильника, ни IWDG — глубокий сон
с пробуждением по WKUP2 (INT1 движение, PASSIVE→WORK) ещё не реализован.
Риск: уснули ждать движения, прерывание не пришло → спим вечно. Нужны ДВА сторожа:

1. **IWDG** (короткий, аппаратный, ~32 с макс на L4 = LSI÷256÷4096): ловит
   зависание кода в активном режиме (WORK/SERVICE), кормить в главном цикле;
   зависание → сброс → мгновенный старт (BOOT0=0).
2. **RTC-будильник** (длинный, периодическое пробуждение, ~мкА от часового
   кварца) — главный «не заснуть навечно». Диапазоны: RTC Wakeup Timer до ~18 ч
   (16-бит/1Гц), с удвоением ~36 ч; RTC Alarm по календарю — сутки/недели.
   Логика: уснули ждать WKUP2 → если за большой интервал RTC всё равно будит →
   проверка состояния (батарея/датчик/наработка) → снова спать или работать.

**Два глубоких режима — выбор (16.06)**: в Standby И RTC, И IWDG работают на
СОБСТВЕННЫХ независимых тактах (LSE/LSI) отдельно от ядра → аппаратная гарантия
пробуждения/сброса в любом случае.
- **Stop2** (~1–2 мкА): ОЗУ цела, мгновенное пробуждение по EXTI (INT1 IMU /
  WKUP2). Основной режим «ждём движения» — быстрый отклик, контекст сохранён.
- **Standby** (десятки–сотни нА): ОЗУ теряется (кроме backup-рег.), пробуждение
  через сброс; независимый сторож RTC/IWDG. Для ОЧЕНЬ долгого простоя (колесо
  стоит неделями) ради батареи, с восстановлением контекста из backup/Flash.
Схема: ожидание движения — Stop2; очень долгое бездействие → Standby.

**ВАЖНО (16.06): потеря ОЗУ НЕкритична — алгоритм на это рассчитан.** Значит можно
смело брать самый глубокий режим (Standby/Shutdown) ради максимальной экономии
батареи LS14250, не держась за Stop2 ради RAM. Пробуждение по WKUP2 = холодный
старт, с BOOT0=0 мгновенный. Стыкуется с форматом «stub+дозапись»
(data_format_spec_v1.md): timestamp_start пишется во Flash в начале цикла, остаток
копится в RAM и дописывается в конце; при сбросе посреди цикла запись = CRC 0xFF
(незавершённая), теряется максимум 1 незакрытый цикл. Потеря RAM уже заложена.
⇒ склоняемся к Standby как основному режиму ожидания (не Stop2).

**Backup-регистры — НЕ использовать (16.06)**: backup-домен на VBAT; отдельной
батарейки нет → VBAT соединён с VDD → регистры/RTC переживают Standby/Shutdown,
пока LS14250 подключена, и теряются только при СНЯТИИ батареи (вероятность мала).
Но решено НЕ зависеть от них вовсе — алгоритм самовосстанавливается из Flash на
каждом холодном старте: указатель записи = двоичный поиск первой пустой ячейки;
наработка = из последней записи Flash; время = теряется при снятии батареи
(RTC→2000), восстанавливается синхронизацией в активации. Цикл после замены
батареи: подключил → активировал (синхр. времени) → поехал. Максимальная
устойчивость: переживает и сброс посреди цикла, и полное снятие батареи —
всё критичное в энергонезависимой Flash, не в backup-регистрах.

   («помогало передёрнуть питание»). Теперь детерминированно. Выход не изменён
   (WKUP1 low 3 c).
3. **STM32 temp + VDDA — безопасно, по запросу**: новая `stm_adc_read(vdda,temp)`
   в stm_temp.c (полный bring-up ADC с таймаутами, без Error_Handler, не в
   Service-init → сбой не рвёт связь). `cmdGetTempChip` (0x11) теперь отдаёт

Оба — отсутствие инициализации периферии в SERVICE-ветке (`com.c Service()`);
раньше периферию поднимала только WAKE-ветка (`command.c`). Перешить CubeIDE.

1. **TMP117 + FRAM возвращали 0.00 °C**: добавлены `tmp117Activ()` + `framActiv()`
   в начало `Service()` (+ `#include "pwr.h"`).
2. **STM32 internal temp — мусор**: `calc_vref()` и `ADC1_Temp_Channel_Init()`
