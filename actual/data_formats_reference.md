# LogLSM — Форматы данных во Flash (справочник)

> Актуально на 28.07.2026. Единая шпаргалка по форматам записи в NOR Flash,
> чтобы не искать по заметкам. Подробная спека полей — `data_format_spec_v1.md`.

## Общий принцип — «слово» и маркёр

- **Слово = страница NOR Flash = 256 байт.** Минимальный физический блок.
- **Байт [0] каждого слова = МАРКЁР типа.** По нему декодер выбирает формат.
  Маркёрное пространство ЕДИНОЕ для Регистратора и Логгера («разницы нет —
  просто данные декодируются по-разному»).
- **`0xFF` = пусто = конец журнала** (стёртый NOR). Поиск позиции записи и
  разбор идут до первого слова с `[0]==0xFF`.
- Формат записи Регистратора задаётся командой **`REC_FORMAT` (0x31)**:
  payload[0] = 0 базовый / 1 уплотнённый / 2 подробный. Прошивка пишет
  соответствующий маркёр. Выбор — на весь рабочий цикл (чип стирается перед
  выездом, журнал однородный; смешанные слова допустимы и читаются, но в норме
  не возникают).

## Таблица маркёров (единое пространство)

| Маркёр [0] | Формат | Записей в слове |
|---|---|---|
| `0xFF` | пусто / конец журнала | — |
| `0xF5` | **Регистратор БАЗОВЫЙ** | 1 |
| `0xF3` | **Регистратор УПЛОТНЁННЫЙ** | до 5 |
| `0xF4` | **Регистратор ПОДРОБНЫЙ** (резерв) | 1 + приложение |
| `0xFE` | Логгер: ЗАГОЛОВОК цикла | 1 фрейм |
| `0xFD` | Логгер: ДАННЫЕ (сэмплы) | 1 фрейм |
| `0xFC` / `0xFB` | Логгер: СТАРТ+Д+T0 / +T1 | 1 фрейм |
| `0xFA` | Логгер: ДАННЫЕ+E1 (темп/статус) | 1 фрейм |
| `0xF8` / `0xF7` | Логгер: ДАННЫЕ+E3 / +E4 (часы-чекпойнт) | 1 фрейм |
| `0xF6` | Логгер: СТОП цикла | 1 фрейм |

Регистраторные маркёры (`0xF5/0xF4/0xF3`) выбраны НИЖЕ логгеровского диапазона
`0xF6…0xFE` — детект режима по первому байту (`b0>=0xF6 && b0<=0xFE → Логгер,
иначе Регистратор`) остаётся однозначным.

## РЕГИСТРАТОР — 3 формата

Базовая запись цикла — **48 байт**, одинакова во всех трёх форматах; различается
только сколько их в слове и маркёр. Всё little-endian.

### Базовая 48-байтная запись (тело)

| Смещ. (в записи) | Разм. | Тип | Поле |
|---|---|---|---|
| 0 | 4 | u32 | tsStart — unix-сек начала цикла |
| 4 | 4 | u32 | duration — длительность цикла, сек |
| 8 | 4 | u32 | duration_total — накопленная наработка, сек |
| 12 | 4 | f32 | rpm_max — макс. скорость, об/мин |
| 16 | 4 | f32 | rpm_avg — средняя скорость, об/мин |
| 20 | 4 | f32 | vib1_peak — пик вибрации кан.1, мг |
| 24 | 4 | f32 | vib1_rms — уровень кан.1, мг |
| 28 | 4 | f32 | vib2_peak — пик кан.2 (удары), мг |
| 32 | 4 | f32 | vib2_rms — rms кан.2, мг |
| 36 | 1 | u8 | temperature — raw = °C+60 |
| 37 | 1 | u8 | status — voltage_zone[2:0] |
| 38 | 1 | u8 | rec_version = 2 |
| 39 | 1 | u8 | variant_flags = 0x0A (вариант A) |
| 40 | 6 | — | reserved = 0 |
| 46 | 2 | u16 | CRC16-CCITT (poly 0x1021, init 0xFFFF) по байтам [0..45] |

Признаки: `ts==0xFFFFFFFF` — слот не записан; `CRC==0xFFFF` — запись прервана
(broken, разбор продолжается).

### 1. БАЗОВЫЙ (маркёр `0xF5`) — 1 цикл = 1 слово
```
[0]        0xF5
[1..48]    базовая запись (48 Б)
[49..255]  0xFF (не используется)
```
Простой, «дорогой» по ёмкости (1 запись/страницу). Ёмкость ≈ 65 535 циклов.

### 2. УПЛОТНЁННЫЙ (маркёр `0xF3`) — до 5 циклов в слове
```
[0]          0xF3
[1..48]      запись 0
[49..96]     запись 1
[97..144]    запись 2
[145..192]   запись 3
[193..240]   запись 4
[241..255]   0xFF (хвост)
```
«Старая» плотная упаковка — ×5 ёмкость (≈327 675 циклов). Слоты заполняются по
циклам; маркёр пишется один раз при открытии слова, дальше дозапись в слот.
Незаполненный хвостовой слот = `ts==0xFF` (не конец журнала — конец записей
слова; конец журнала = пустое СЛЕДУЮЩЕЕ слово `[0]==0xFF`).

### 3. ПОДРОБНЫЙ (маркёр `0xF4`) — РЕЗЕРВ, не реализован
```
[0]        0xF4
[1..48]    базовая запись (48 Б)
[49..255]  приложение (207 Б) + свой CRC — состав НЕ определён
```
Модель: подробное = базовое + приложение. Кандидаты в приложение: подскорости
детектора полок (сейчас в Flash не сохраняются), профиль температуры/напряжения
по циклу, счётчики сбросов сторожа, расширенная вибро-статистика. Декодер уже
толерантен к `0xF4` (читает базовую часть [1..48]); тело пока = базовое.

## ЛОГГЕР — 1 формат (потоковый)

Непрерывный поток сырых сэмплов IMU. **1 фрейм = 1 слово = 1 страница (256 Б).**
Байт [0] = тип фрейма (см. таблицу маркёров выше). Внутри — сэмплы
Ax/Ay/Az/Gx/Gy/Gz по 12 байт, до 21 сэмпла/фрейм, аппаратный auto-range (FS-байт
в каждом фрейме). Начало цикла — `0xFE` (заголовок) или `0xFC`+`0xFB`
(старт+часы), завершение — `0xF6` (СТОП с длительностью и накоплением).
Раскладка фреймов — `data_format_spec_v1.md` §«Режим 2 — Logger v2».

Коэффициент/FS нужен ТОЛЬКО Логгеру (пишет сырьё на высокой ODR); Регистратор
хранит уже готовые физические результаты (об/мин, мг), FS в записи нет.
