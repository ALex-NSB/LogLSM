- **LOGLSMA** (прошивка): `26.07.26 00:12` (FW_DD=26, FW_HH=0, FW_MI=12)

Последние архивы: `W_2026-07-26_01-05.zip`, `A_2026-07-26_00-12.zip`

## Открытый вопрос (начать отсюда)
**Замер скорости ЗАПИСИ даёт абсурдные цифры.** По эталонной секунде RTC:
- чтение: 80 МГц → 4303 стр/с, 5 МГц → 1093 стр/с (корректно, частота влияет)
- запись: 50000 стр/с (80 МГц) / 46296 (5 МГц) — **мусор**, запись физически
  не может быть в 10 раз быстрее чтения (у неё ещё и стирание).

Гипотеза: в режиме `mode==0` обработчика `cmdFlashSpeedTestHandler` (0x2D)
вызовы `P25Qx_QPI_ErasePage` / `P25Qx_QPI_ProgramPage` вылетают сразу
(ошибка режима / чип не готов / EnableWrite не проходит), цикл крутится
вхолостую и накручивает счётчик. Проверить: возвращаемые статусы HAL внутри
драйвера, реально ли меняется содержимое флеша после замера записи.

## Что сделано и РАБОТАЕТ

### Разгон Сервиса до 80 МГц (главное, зафиксировано как приоритет)
- Приоритет проекта: **минимальное время считывания** (параметр для потребителя).
- `ServiceClock_Config()` в Core/Src/main.c переписан на **PLL 80 МГц**:
  HSI(16)/PLLM=2 ×PLLN=20 /PLLR=DIV2, `FLASH_LATENCY_4`, SYSCLK=PLLCLK.
- Добавлена `WorkClock_Config()` — прежние **16 МГц** на HSI, PLL выключен.
  Вызывается на boot (до инициализации периферии) и при выходе Сервиса
  в «Работу». Рабочие энергорежимы/сон рассчитаны на 16 МГц — не тронуты.
- UART 921600 выживает: `ComInit()` внутри `Service()` переинитит USART под
  новую `SystemCoreClock` (HAL считает делители от неё).
- Проверено на железе: сервис стартует, связь держит, запись/чтение работают.

### Команда 0x2C — реальная частота флеша
- `FLASH_SET_FREQ = 0x2C`, payload[0] = индекс 0..4 → **80/40/20/10/5 МГц**
  (`ClockPrescaler` 0/1/3/7/15 от HCLK=80). Меняет делитель + `HAL_QSPI_DeInit/Init`,
  затем `P25Qx_Reset` и (если был quad) `P25Qx_SetQuadSpi` — софт и чип синхронны.
- Список «МГц» в UI перестал быть заглушкой, реально шлёт команду.
- Раньше стоял `hqspi.Init.ClockPrescaler = 255` (при HCLK 16 → флеш ~62 кГц!).

### Команда 0x2D — замер скорости по ЭТАЛОНУ RTC
- Отдельная кнопка **«Скорость»** (обычный постраничный обмен НЕ трогали —
  по прямому указанию Ed: «для измерения нужны специальные условия, по
  отдельной кнопке можем делать что хотим»).
- payload: [0]=режим (0=запись, 1=чтение), [1..4]=старт.страница, [5..8]=страниц.
- Прошивка синхронизируется на границу секунды RTC, гоняет операции **5 секунд**,
  считает страницы, возвращает **страниц/с** (count/5). Ответ: [0]=err, [1..4]=uint32 LE.
- Приложение: страниц/с × 256 / 1024 = КБ/с, показывает две цифры
  (формат должен быть `84/152 КБайт`, стенография `W../R..` заменена в 01.05).
- Кнопка запускает mode=0, по ответу цепочка сама шлёт mode=1 (флаг
  `m_speedWrKbps < 0` = ждём запись). Таймаут на время замера поднят до 30 с,
  возвращается к `spinTimeout` после второй фазы.

### Исправленные баги (LOGLSMW)
1. **«Занято» при нескольких циклах** — считалось от сквозного `pagesDone`,
   во 2-м цикле счётчик уползал вверх и в конце откатывался.
   Фикс: позиция внутри цикла `(pagesDone-1) % pageTotal`.
2. **Проскок «лишнего цикла» после «готово»** — автодамп после записи обновлял
   панель по ходу своего прогона. Фикс: при `m_restoreTestAfterDump` не звать
   `memTestUpdateUi()` на шагах дампа (панель держит замороженный результат).
3. **«Байт»/Факт пустой после записи** — `TagWriteVerify` читал байт, но не
   писал в `m_test.lastReadByte`. Фикс: заносим.
4. **«Адрес» не обновлялся при обычной записи** — теперь обновляется ПО ХОДУ
   записи (как «Байт»), на текущую записываемую страницу.
5. **Отступы hex-дампа** — `"  %1:  "` → `" %1: "`, влез ещё столбец.
6. Кнопки вынесены **в два ряда**: Запись/Чтение, ниже Скорость + индикатор.
   Панель «Данные» сужена до 230 px.
7. Дефолт «Старт»/Задать = **2**, и для старта ≤ kLogStartPage предупреждение
   «Запись не на границе» больше не выводится (обход служебной стр.0 — норма).

## Нумерация страниц — ОКОНЧАТЕЛЬНО (важно!)
Ed настаивал на этом несколько раз, путать нельзя:
- **Адрес 0 = страница 1** на экране. Служебной страницы ПЕРЕД данными нет.
- Операции работают **адресом**, а не «количеством занятых» — это разные величины.
- **«Занято» = реально записанные (непустые) страницы**, «ей неважно
  служебная или нет». Стёртый чип = **0**. Источник — бинарный поиск первой
  FF-страницы (реальная проверка после любых вариаций), от адреса 0.
- Все три места приведены к одному: панель «Занято», лог-строка
  `flashBinSearch`, бар памяти — везде `used = m_firstFreePage` без вычета
  `kLogStartPage`. После полного стирания `m_firstFreePage = 0`.
- **Групповые операции** (образ RG/LOG, термотест) служебную стр.0 обходят:
  старт = `qMax(m_firstFreePage, kLogStartPage)`. Ручные «Запись»/«Чтение»
  пишут куда указано, в стр.1 — с предупреждением.

## Что выяснено экспериментально про скорость (не повторять ошибок)
- **Скорость записи флеша от частоты SPI и числа линий почти не зависит** —
  лимит в `Wait_Busy` (чип программирует страницу ~мс, это свойство кристалла).
  Запись 50 страниц: SPI 5 МГц → 146 КБ/с, SPI 80 → 159, SPIx4 80 → 159,
  SPIx4 5 → 159. Это физика, а не баг.
- **Постраничные накладные маскируют частоту**: 50 чтений по 256 байт —
  setup QSPI-команды на каждую страницу доминирует. Чтение постранично:
  SPI 5 → 582 КБ/с, SPI 80 → 842, SPIx4 5 → 820, SPIx4 80 → 843
  (на 80 МГц оба режима упираются в ~843 = потолок накладных).
- Первый замер по таймеру ПК (UART в измерении) давал 2-14 КБ/с — недостоверно,
  мерил тракт ПК↔UART↔МК, а не флеш. Отброшен.
- Замер по DWT-тактам давал сомнительные 152 КБ/с при 80 МГц — Ed счёл
  недостоверным («послушать тебя, так быстрее килобит в секунду не прочитать»).
  Отброшен в пользу **эталонного интервала RTC**.
- ВАЖНО: `HAL_QSPI_Receive` работает программным поллингом FIFO через CPU —
  реальный потолок определяется процессором, а не линией SPI. Для честной
  скорости линии понадобился бы DMA / memory-mapped QSPI (не делали).

## Прочее из прошивки
- `P25Qx_QPI_ProgramPage` / `QPI_Read` корректно ветвятся по `handle->mode`
  (standart/quadspi/qpi) — замер работает в обоих режимах SPI/SPIx4.
- `QSPI_Receive` ставит `DLR = size-1` (32-битный) — блоки >256 байт читает
  за один transfer, ограничения нет.
- Аккумуляторы времени в `cmdReadMem`/`cmdWriteMem` (вариант «копить по ходу
  постраничных операций») были добавлены и **удалены** — постраничный обмен
  решили не трогать.

## Грабли сессии (техническое)
- `str_replace` при вставке функций в com.c один раз **съел определение**
  `cmdFlashReadHandler` → ошибка линковки `undefined reference`. Проверять,
  что old_str полностью возвращён в new_str.
- Аккумуляторы объявлялись НИЖЕ первого использования → `undeclared`.
  Объявления в C ставить до использования.
- В архив забыл включить `mainwindow.h` при добавлении члена класса →
  `m_speedBytes was not declared`. Всегда включать h, если менялся.
- ST-LINK может отвалиться с `Target USB comms error` / `DEV_USB_COMM_ERR` —
  это Devin/gdb-server держит адаптер. Лечится сбросом питания /
  переподключением USB. Прошивка тут не виновата. ELF лежит в
  `Firmware\LOGLSMA\build\Debug\LOGLSMA.elf`, можно шить CubeProgrammer'ом.
- Warning'и в `myfunc.c` (unused variable 'pvalue', control reaches end of
  non-void function) — не наши, не критичны, игнорируем.
