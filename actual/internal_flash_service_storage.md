# LogLSM — Служебное хранилище во внутренней Flash STM32L433 (design)

> Design-док, зафиксирован 06.07.2026. Чтобы не переделывать и не потерять.
> Реализация — стадиями (сначала счётчики, потом паспорт/конфиг).
> МК: STM32L433CC, 256 КБ Flash, страница 2 КБ, 128 страниц.

---

## 0. Зачем
Одна-две страницы внутренней Flash под служебные данные, которые:
- **переживают потерю питания** (батарейка в зажиме + вибрация оси колеса →
  кратковременные разрывы контакта; backup-регистры при этом гаснут, Flash — нет);
- доступны **сразу на загрузке**, без инициализации внешнего QSPI-чипа/QPWR.

Закрывает разом: счётчики рестартов (потеря питания / watchdog), «паспорт»
устройства (серийник/вариант/дата), конфиг (пороги/ODR/режим — сейчас
захардкожены в `Data.h`), и опору для восстановления состояния после сброса.

---

## 1. ⚠ КРИТИЧНЫЕ ограничения внутренней Flash L4 (диктуют раскладку!)
1. **Программирование только двойными словами (64 бита / 8 байт)** за операцию.
2. **ECC: каждое двойное слово можно запрограммировать РОВНО ОДИН раз** после
   стирания. Повторная запись в то же 64-битное слово (даже «догасить биты
   1→0») → **ECC-ошибка** (в отличие от внешней NOR/старых STM32 без ECC).
   → **Битовый трюк «гашу по одному биту в том же байте» на L4 НЕ работает.**
   → Событие = **новое двойное слово (8 байт) целиком.**
3. **Стирание — только целой страницей (2 КБ).** Стёрто = все `1` (0xFF).
4. Разные паттерны доступа (накопление слотами vs перезапись) → **разные
   страницы** (иначе перезапись конфига стёрла бы счётчики).

---

## 2. Размещение страниц
Прошивка ~62 КБ = ~31 страница (0..30) из 128. Свободно **~97 страниц** —
запаса вагон. **Резервируем 5 последних страниц** (123..127) под служебное
хранилище: 4 под многостраничный журнал событий + 1 под паспорт/конфиг.
Прописать в linker script (сдвинуть верх кода), чтобы растущая прошивка их не
заняла.

| Страница | Адрес | Назначение | Паттерн |
|---|---|---|---|
| **123** | `0x0803D800` | **Page B — Паспорт + Конфиг** (1 стр.) | стирание+перезапись |
| **124..127** | `0x0803E000..0x0803FFFF` | **Page A — Журнал событий** (4 стр. = 8 КБ = **1024 слота**) | накопление слотами |

(2 КБ = 0x800; база 0x08000000; page N = 0x08000000 + N·0x800.)
Журнал теперь не просто счётчик, а **форензик-лог сбросов** на 1024 события:
видно не только «сколько раз», но и «где по наработке» и «чем» (питание/зависон).

---

## 3. Page A — «Счётчики/события» (стр.127 @ 0x0803F800)
**Формат: массив 8-байтных слотов** (2048 / 8 = **256 слотов на страницу**).
Каждое событие занимает один эрзац-слот (двойное слово), т.к. ECC (см. §1.2).

**Раскладка слота (8 байт):**
```
[0]   тип события: 0xF0 = потеря питания (POR/BOR/backup стёрт)
                   0xF1 = watchdog-рестарт (IWDG)   (опц., см. ниже)
[1]   причина/флаги RCC (маска)
[2..5] totalSec на момент события (u32) — привязка «где в наработке рвануло»
[6..7] CRC8/резерв
```
**Счётчик = число НЕ стёртых слотов** данного типа (скан страницы на загрузке).
**Инкремент** = найти первый стёртый слот (все 8 байт = 0xFF), записать в него.
**Ёмкость: 256 событий**; при заполнении — стоп счёта или стирание (провижн).

**Что кладём:**
- **Потеря питания** — обязательно (главный смысл; переживает питание).
- **Watchdog-рестарт** — можно сюда же (единый журнал событий) ИЛИ в
  backup-регистр (он переживает watchdog, т.к. питание при нём живо). Решение:
  **для единообразия и истории — тоже в Page A** (тип 0xF1). Backup оставляем
  под «живое» состояние между Stop2, не под счётчики.

## 4. Page B — «Паспорт + Конфиг» (стр.126 @ 0x0803F000)
**Формат: перезаписываемый блок.** Изменение = прочитать в ОЗУ → стереть
страницу → записать заново двойными словами. Пишется редко (провижн/смена
конфига).

**Раскладка (двойными словами, 8-байтное выравнивание):**
```
Offset  Size  Поле
0x000   8     Маркер+версия: 0xBEBExxxx... (валидность; иначе → дефолты из Data.h)
0x008   16    Серийный № (ASCII, дополнен 0x00)          ]
0x018   1     Вариант платы (A=0xA0 / B=0xB0 …)          ] ПАСПОРТ
0x019   3     Дата выпуска (год-2000, месяц, день)        ]
0x01C   4     резерв паспорта
0x020   2     MIN_CYCLE_SEC                                ]
0x022   2     GYRO_THRESHOLD                               ]
0x024   1     ROTATION_DEBOUNCE_N                          ]
0x025   1     CONFIRM_WINDOW_POLLS                         ] КОНФИГ
0x026   2     RTC_WAKE_PERIOD_S (период RTC-wake, с)       ] (заменяет хардкод
0x028   2     IWDG_TIMEOUT_S (таймаут сторожа, с)          ]  в Data.h)
0x02A   1     ACC_FS / 0x02B GYRO_FS / 0x02C ODR-код       ]
0x02D   1     режим записи (Регистратор/Logger)           ]
0x02E   …     резерв под будущий конфиг
0x7F8   8     CRC32/маркер конца блока
```
**На загрузке:** прочитать; маркер валиден → грузим конфиг в ОЗУ; невалиден →
**компилируемые дефолты из `Data.h`** (устройство работает «из коробки» без
провижна).

## 5. Поток на загрузке (main(), рано)
1. `StandbyDetectWakeCause()` — флаги PWR (SB/WUF1/WUF2)+RTC WUTF (уже сделано, Стадия 1).
2. **Определить потерю питания:** backup-маркер (0xBEBE в BKPxR) невалиден
   ИЛИ RCC PORRST/BORRST → был power-loss. Если да — **записать событие 0xF0 в
   Page A** (+ восстановить backup-маркер). RTC при этом сброшен (→1996) —
   принимаем (см. §7).
3. **Watchdog:** RCC IWDGRST (backup жив) → записать событие 0xF1 в Page A.
4. `__HAL_RCC_CLEAR_RESET_FLAGS()`.
5. Загрузить **конфиг** из Page B (или дефолты).
6. **Восстановить состояние из внешней Flash:** `LoadTotalSec` (totalSec),
   `flashFindWritePos` (курсор) — уже есть.
7. Дальше — по `g_wakeCause` (Стадии 2–4: Standby-логика).

**GET_STATS** отдаёт: `restarts_timer` = число слотов 0xF1, `restarts_power` =
число слотов 0xF0 (скан Page A) → поля «Перезапуски» на дашборде оживают.

## 6. Провижн / инициализация ПЕРЕД РАБОТОЙ (правка пользователя 06.07.2026!)
Отдельная процедура (по команде из SERVICE), выполняется один раз перед
установкой в поле / при переинициализации. **ОБЯЗАТЕЛЬНО сбрасывает счётчики:**
1. **Стереть Page A** (стр.127) → все счётчики событий = 0 (чистый старт в поле).
2. Записать **Паспорт** (серийник/вариант/дата) в Page B.
3. Записать **Конфиг** (дефолты или заданные) в Page B.
4. Выставить backup-маркер 0xBEBE.
> Без п.1 старые стендовые/отладочные рестарты попадут в полевую статистику —
> обязательно обнулять при провижне.

---

## 7. Время при потере питания (договорённость)
RTC теряет ход при потере питания (→ 1996), пока VBAT не подпитан. Принимаем:
записи продолжаются от «повреждённой» точки на относительной `durationTotal`;
абсолютные метки **корректируем/выравниваем постфактум**, точки разрыва
помечены счётчиком 0xF0 в Page A. **Будущая версия** (большой конденсатор/
бэкап-батарея на VBAT) снимет и это (RTC не потеряет ход, backup переживёт
провал) — тогда часть механики упростится, но формат страниц не меняется.

---

## 8. Порядок реализации
1. **Драйвер внутренней Flash** (unlock/erase page/program double-word/read) — App-модуль.
2. **Page A: счётчик потерь питания** (immediate) — запись 0xF0 на загрузке при
   power-loss, скан для счёта, GET_STATS. Проверка на железе (IWDG даст 0xF1).
3. **Page B: паспорт + конфиг** — загрузка конфига (дефолты из Data.h как
   fallback), команды GET/SET паспорта и конфига из LOGLSMW.
4. **Провижн-команда** (сброс Page A + запись паспорта/конфига).
5. Интеграция конфига в логику (пороги/ODR/период RTC/таймаут IWDG из Page B).
