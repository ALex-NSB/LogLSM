# LogLSM — сводка сессии 28.07.2026 (вечер) — для продолжения

## 🚩 ТОЧКА ВХОДА
**Версии:** A = `26.07.28 18:05` (Data.c/com.c), W = `26.07.28 18.41` (main.cpp).
Формат версии — ГОД-ПЕРВЫМ (ГГ.ММ.ДД), день-первым пробовали и откатили.

**Главное за сессию: НОВЫЙ ФОРМАТ ХРАНЕНИЯ «1 цикл = 1 слово».**
- Слово = страница 256 Б. Байт **[0] = маркёр типа**, запись цикла с **offset 1**.
  Коды: `0xFF` пусто/конец · `0xF5` базовая запись Регистратора · `0xF4`
  расширенная (РЕЗЕРВ, хвост [49..255] определим позже). Логгер — `0xF6…0xFE`
  (маркёрное пространство единое). Базовый 48-байтный формат записи НЕ менялся,
  просто переехал в слово за маркёр. 1 запись = 1 страница (было 5/страницу).
- Конец журнала/поиск позиции — по `word[0]==0xFF` (не по `ts`).
- **ПРОВЕРЕНО НА ЖЕЛЕЗЕ:** образ грузится, «Данные» разбирают верно, несколько
  образов идут ВСТЫК и разбираются сквозь границы (прерванная запись CRC=FFFF не
  рвёт разбор — только пустая страница = конец). Темп-волны до 149 °C, обороты/
  вибрация/удары на местах. Версии A/W совпали (сборка свежая).

## Открытые задачи (по приоритету)
1. **Типы записей в маркёре [0] + выбор формата в настройках (план на след.
   сессию, СОГЛАСОВАНО 28.07):**
   - Расширить таксономию маркёра: помимо `0xF5` базовая и `0xF4` расширенная —
     добавить тип **«база уплотнённая»** (компактная базовая запись; код напр.
     `0xF3`). Итого варианты записи: уплотнённая / базовая / расширённая.
   - В **Настройках** LOGLSMW — выбор ТИПА расширенного формата записей:
     **«уплотнённый»** или **«подробный»**. Прибор пишет выбранный тип, маркёр
     [0] говорит декодеру, что за формат.
   - **Расширенная запись `0xF4`** — состав хвоста [49..255] (207 Б) определить.
     Кандидаты: подскорости детектора полок (сейчас в Flash НЕ сохраняются!),
     профиль температуры/voltage_zone по циклу, счётчики сбросов сторожа, расшир.
     вибро-статистика. Модель: расширенное = базовое [1..48] + приложение + CRC.
   Делаем «по ходу», базовый формат (0xF5) уже работает и проверен.
2. **🔴 Рабочий цикл флеша — на ОБЫЧНЫЙ SPI (1-линия), QPI только для выгрузки.**
   Сейчас `flashActiv()` (pwr.c) зовёт `P25Qx_SetQPI` на КАЖДОМ включении → и
   рабочая запись идёт в QPI. Надо: расщепить бринг-ап на рабочий (SPI 1-линия,
   без SetQPI) и сервисный/выгрузка (QPI+memmapped); сделать 1-линейные Read/
   ProgramPage (в драйвере команды с QSPI_INSTRUCTION_1_LINE уже есть). Причина —
   надёжность/простота автономного пути (убрать QPI-залипание из поля). НЕ энергия.
   СОГЛАСОВАНО, НЕ СДЕЛАНО.
3. **Кэш `write_ptr` в ОЗУ** (Stop2 сохраняет SRAM) — убрать растущий скан
   `flashFindWritePos` каждую запись; пересканировать только на холодном старте.
   Крупнейший энергетический рычаг по флешу (крупнее «5→1»). НЕ сделано.
4. Из прошлого handoff (не закрыто): персистентное безопасное хранение ts
   активации (не в горячей внутр. Flash); автозапуск «Работа» (0x1D) в финале
   активации + стоп активного опроса + индикатор «регистратор в работе».

## Решённое по ходу (чтобы не переоткрывать)
- Ёмкость при 1 цикл/слово: ~65 535 циклов; при 10мин+10мин ≈ **2.5 года 24/7**
  до заполнения. ×5 потеря ёмкости не критична (чип и так считался под Логгер).
- Маркёр — ТОЛЬКО пер-слово (пер-слотовых маркёров НЕТ). Внутри слова формат
  известен, отдельные записи не метятся.
- Накопление 5→1 ради энергии — НЕ делаем (выигрыш пренебрежим, привязывает к
  Stop2, риск потери циклов). Энергию чинить кэшем write_ptr (п.3).
- **«3 образа → 1»** — было верно для реального лога (стоп на первом FF). В новом
  формате образы встык разбираются сквозь границы (broken-tail не рвёт). ✅
