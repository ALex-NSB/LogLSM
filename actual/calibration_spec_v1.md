## Принцип (жёсткое ограничение, 12.07.2026)

**Вся калибровочная аппаратура — на СТЕНДЕ. В рабочем приборе НИКАКИХ
калибровочных модулей нет (ни GPS, ни счётчика).** Прибор несёт только штатное
(LSE-кварц, TMP117, внутренняя Flash STM32) и делает ровно две вещи:
1. **хранит** коэффициенты калибровки (внутренняя Flash — переживает стирание
   лога и потерю питания);
2. **применяет** их в работе (RTC smooth-calib + температурная поправка по
   TMP117; коэффициент скорости).

Всё измерение/вычисление коэффициентов — на стороне стенда, через сервисный
разъём (существующий LTP-тракт через Nucleo, адресация 0x8C/0x8D). Разовая
операция при выпуске/поверке, не в поле.

**Разделение ролей:**
- **Прибор (LOGLSMA):** хранит + применяет. Отдаёт наружу измерительный сигнал
  (RTC_CALIB). Принимает и сохраняет коэффициенты/время по LTP.
- **Стенд:** GPS-модуль (эталон) + счётчик/захват. Меряет уход кварца, считает
  коэффициенты, пишет их в прибор. GPS до прибора не доезжает.
- **LOGLSMW:** оркестрирует (вкладка «Калибровка»), показывает, инициирует.

## 1. Частота RTC (кварц LSE 32.768 кГц) — постоянный член

**Механизм в чипе — RTC smooth calibration** (`RTC_CALR`), НЕ изменение делителя:
- окно калибровки = **2²⁰ циклов LSE = 32 с**;
- `CALM` (0…511) — маскирует лишние импульсы за окно (правит БЫСТРЫЙ кварц);
- `CALP` (+512 за окно) — добавляет (правит МЕДЛЕННЫЙ);
- шаг `CALM` = 1 импульс / 2²⁰ = **0.954 ppm**; диапазон ≈ −487…+488 ppm;
- прямое соответствие: если за 32 с генератор даёт с избытком Δ импульсов →
  `CALM = Δ`; в ppm `CALM = (Δf/f)·2²⁰`.
- API: `HAL_RTCEx_SetSmoothCalib` (можно вызывать на ходу — регистр под это сделан).

**Нужен ВНЕШНИЙ эталон** (LSE себя не измерит; MSI/HSI ±1% не годятся). Варианты:
- **GPS-PPS на стенде (основной)** — 1 PPS привязан к UTC (±десятки нс),
  абсолютный, дешёвый, воспроизводимый, без поверенного частотомера. Стенд
  гейтит сигнал RTC_CALIB прибора по PPS, считает частоту → `CALM/CALP`.
- **Дрейф против ПК на длинном прогоне (запасной, уже есть)** — Δ «Общее» на
  вкладке «Стенд» = измеренная ошибка LSE (ppm = Δс / T · 10⁶). Грубее, дольше,
  но механизм уже собран.
- (лабораторный частотомер с TCXO/OCXO на RTC_CALIB — если есть; GPS удобнее).

**Аппаратный крючок — вывод RTC_CALIB на сервисном разъёме** (заложен в железе,
детально не прорабатывался). Отдаёт калибровочный сигнал RTC: 512 Гц по
умолчанию, 1 Гц через бит COSEL.

**Нюанс разрешения (выбор метода на стенде, не блокер):** до шага 0.954 ppm с
выхода 512 Гц за 32 с не дотянуться (16384 отсчёта ≈ 61 ppm/отсчёт). Либо
длинный гейт (сотни–тысячи секунд), либо **реципрокный счёт** — ловить фронты
1 Гц прибора и PPS быстрым таймером стенда (80 МГц) и мерить набег разности фаз
за много секунд.

## 2. Частота RTC — температурный член

Постоянный член (§1) верен только на температуре калибровки. Часовой кварц —
**параболика**: f(T) = f₀·[1 − β·(T−T₀)²], β ≈ 0.035 ppm/°C² (±), вершина
T₀ ≈ 25 °C. В поле при −20 °C добавляется ~70 ppm (~6 с/сутки) — мимо.

**Компенсация в приборе (программный TCXO):** периодически читать TMP117 →
считать поправку β·(T−T₀)² → перезаписывать `RTC_CALR` (SetSmoothCalib на ходу).
Итог = постоянный `CALM/CALP` (§1) + температурная добавка. β/T₀ — из даташита
кварца или характеризации партии в термокамере; хранятся в Flash прибора.

Открыто: непрерывная формула vs таблица поправок по температуре; период
перезаписи; гистерезис, чтобы не дёргать `RTC_CALR` на каждый шум TMP117.

## 3. Абсолютное время (посев)

GPS даёт не только частоту, но и **UTC (NMEA + PPS)** — тем же жестом на стенде
засеять RTC прибора точным временем (ранее не затрагивалось). Запасной вариант —
время ПК из LOGLSMW. Команда LTP «установить время» (нужна, см. ниже).

---

## 4. Скорость вращения

`SPEED_CALIB_COEF` (Data.h/HandleSensorData). Сейчас **1.0 (нейтральный)**.
Одноточечный 1.057 (снят на 74 об/мин) дал утром +4–5% из-за температурного
дрейфа → одна точка не годится. Нужна **многоточечная калибровка** (таблица
коэффициентов по скорости) **с температурной поправкой** (TMP117). Эталон —
заданная стендом скорость (ПК её и командует, уже известна точно). Коэффициенты
хранятся в Flash прибора.

Открыто: структура таблицы (узлы по скорости), интерполяция, форма темп-поправки
для скорости (отдельная от временной).

**Прошивка LOGLSMA (LTP-команды + хранение во внутренней Flash STM32):**
- вкл/выкл вывода RTC_CALIB (+ выбор 512 Гц / 1 Гц, COSEL);
- get/set `CALM/CALP` (постоянный член);
- get/set температурных параметров кварца (β, T₀);
- get/set коэффициента(ов) скорости;
- set абсолютного времени RTC;
- применение: температурная перезапись `RTC_CALR` по TMP117 в рабочем цикле.
- Хранилище — внутренняя Flash STM32 (HAL_FLASH_Program по LTP в сервисе;
  переживает стирание лога). Ложится рядом с «паспортом устройства»
  (см. корневой CLAUDE.md, «Паспорт и защита данных»).

**Стенд (Nucleo):** GPS-модуль (PPS + NMEA), захват/счёт RTC_CALIB прибора,
вычисление `CALM/CALP`, отдача в прибор по LTP.

**LOGLSMW:** вкладка «Калибровка» (`tabCalibration`, сейчас заглушка) —
запуск процедур, отображение измеренного ppm/дрейфа/температуры, запись
коэффициентов, посев времени. Единое место для всех калибровок (время + скорость
+ параметры), как задумано в speed-заметке §10.

## Сводка трёх уровней калибровки времени

1. **Постоянный член** — GPS-станция меряет уход LSE → `CALM/CALP` в Flash.
2. **Температурный член** — TMP117 + β, перезапись `RTC_CALR` на ходу в приборе.
3. **Посев абсолютного времени** — GPS UTC → RTC прибора.

Плюс отдельно — **калибровка скорости** (§4): многоточечная таблица + темп-поправка.
Всё меряется на стенде, применяется прибором; в поле — никакой калибровочной
аппаратуры.
