# Рабочий цикл регистратора LOGLSMA — трёхуровневый автомат «Работа»

> Итоговая спецификация. Версия 1.1, 12.07.2026 (вечернее обновление).
> Доведено и подтверждено на стенде (см. хронологию в
> `session_notes_2026-07-11_work_mode_bench.md` и
> `session_notes_2026-07-12_accel_current_odr.md`). Этот файл — чистое описание
> ЦЕЛЕВОЙ схемы, без истории отладки.
>
> Область: режим **«Работа»** (`CMD_START_REGISTER` 0x1D) — автономный полевой
> режим регистратора на вращающейся оси. Отдельно — режим **«Тест»**
> (`CMD_START_TEST` 0x23): тот же детект/запись, но БЕЗ сна (всегда на связи).
>
> **Изменения v1.1 (12.07 вечер):** (1) ODR accel глубокого сна снижен
> 104 → **26 Гц LP (~7 мкА)**; (2) добавлен **гироскоп-троттл Пассивный→Активный
> с эскалацией** (§2.5) — гироскоп как самый дорогой узел включаем редко;
> (3) зафиксированы **термины режимов** (Пассивный/Активный/Сервисный/«между
> землёй и небом», §0); (4) **Standby-ярус РЕШЕНО НЕ делать** — глубокий сон
> остаётся Stop2 (§2.1, §2.4); (5) **«Тест» = эталон точности** времени
> (§7).

---

## 0. Термины режимов (согласовано 12.07.2026)

Пользовательская терминология, на которую ложатся фазы автомата:

| Термин | Что это | Фаза автомата / реализация |
|---|---|---|
| **Пассивный** | Минимальное потребление. accel слушаем всегда (~7 мкА), гироскоп выключен. | ГЛУБОКИЙ СОН (Stop2 + EXTI13) |
| **Активный** | Щупаем accel+гироскоп, при подтверждении — вычисление цикла. Дорогой (гироскоп). | ПРОВЕРКА + ВРАЩЕНИЕ |
| **Сервисный** | Внешнее питание/кабель, UART/USB, все LTP-команды. | `Service()` |
| **«Между землёй и небом»** | «Работа» с кабелем: тот же автономный цикл, но в конце цикла на миг сваливается в Сервисный, отдаёт данные по LTP (`PushCycleRecord`); если команды остаться нет — сразу назад в настоящую «Работу». Отличие от чистого автонома — только эта временная «заставка» обмена. | «Работа» (0x1D) + гейт кабеля (§3) |

Ключевая граница оптимизации автономности — переход **Пассивный→Активный**:
Пассивный держим максимально долго, в Активный (дорогой гироскоп) входим редко
и осмысленно (см. §2.5 — гироскоп-троттл).

---

## 1. Идея

Устройство на оси колеса живёт от батареи LS14250 (цель — годы). Поэтому в
покое оно должно спать максимально глубоко и просыпаться ТОЛЬКО когда колесо
реально крутится, а не на каждое случайное шевеление. При этом на стенде/в
сервисе (подключён кабель) устройство должно оставаться достижимым по LTP.

Отсюда — **три фазы**, и **контроль кабеля** поверх них.

## 2. Три фазы автомата

```

   ┌───────────────────────────────────────────────┐
   │                                                ▼
┌──┴───────────┐   нет вращения,           ┌──────────────────┐
│ ГЛУБОКИЙ СОН  │   долго тишина            │    ПРОВЕРКА        │
│ (DEEP_SLEEP)  │◄──────────────────────────│  (CHECKING)       │
│               │   idleChecks >= порог     │                   │
│ Standby 280нА │                           │ Stop2 + RTC ~2 c  │
│ (сейчас Stop2)│                           │ ОЗУ сохраняется   │
│ accel→WKUP2   │                           │ гироскоп + CONFIRM│
│ RTC ВЫКЛ, ОЗУ✗│                           │ EXTI13 НЕ арм     │
└───────────────┘                           └────────┬──────────┘

                                            │ во Flash + пуш    │
```

### 2.1. ГЛУБОКИЙ СОН (DEEP_SLEEP) = Пассивный
- **Режим: STOP2 + EXTI13 (финал, 12.07.2026).** ОЗУ/контекст сохраняются.
  Гироскоп выключен — единственный живой узел — акселерометр в LP с Wake-Up.
- Будит **движение**: accel-INT через **EXTI13** (Stop2 выходит только по EXTI).
  RTC-будильник в глубоком сне ВЫКЛ — опроса в покое НЕТ.
- Акселерометр на **26 Гц LP (~7 мкА)** — slope-детект ловит пусковую вибрацию
  с 7–8 об/мин на тихом стенде (подтверждено 12.07; в поле вибрация сильнее →
  порог ниже). Спуск по лесенке ODR: 417 HP (170 мкА) → 26 LP (7 мкА) = **×24**.
  1.6 Гц LP (4.5 мкА) на тихом стенде маргинален на низах → отложен до полевой
  валидации; 26 Гц — подтверждённая рабочая точка. `Poll_Sensor` ждёт DRDY
  гироскопа, поэтому ODR accel на измерение не влияет — опускаем свободно ради
  тока.
- **Standby-ярус 280 нА — РЕШЕНО НЕ ДЕЛАТЬ (12.07.2026).** Экономит ~1 мкА на
  фоне 7 мкά accel (<15%), а ресурс LS14250 уже упирается в химию/срок годности
  (10–15 лет), не в наш ток. Плюс цены Standby: выход = сброс МК на КАЖДОЕ
  пробуждение (init periph, энергия boot), риск вернуть мёртвое время, гонка
  boot-пути. **Держим Stop2.** Восстановление после потери ОЗУ (backup+Flash-
  stub) остаётся отдельной задачей НАДЁЖНОСТИ (реакция на аварийный сброс, не
  штатный сон) — см. `wake_architecture_v1.md`.
- **Спин не грозит:** accel-INT (EXTI13) активен только в глубоком сне, где
  мотор стоит и вибрации нет → сыпать нечему.

### 2.2. ПРОВЕРКА (CHECKING)
- Ядро в **STOP2 (1.0 мкА, 1.28 мкА с RTC)** — **ОЗУ НЕ теряется**, контекст
  жив (в отличие от Standby глубокого сна). Будит **периодический RTC ~2 c**;
  EXTI13 НЕ арм (мотор может крутиться — INT1 сыпал бы прерывания).
- На каждом пробуждении: включаем гироскоп, прогрев ~400 мс, **CONFIRM** —
  несколько опросов гироскопа по **DRDY гироскопа** (не accel), окно ~1.2 c.
- Вращение подтверждено (угловая скорость выше порога) → **ВРАЩЕНИЕ**.
- Нет вращения → `idleChecks++`. Набрали порог подряд пустых проверок →
  обратно в ГЛУБОКИЙ СОН.

### 2.3. ВРАЩЕНИЕ (ROTATING)
- Ядро бодрое, гироскоп непрерывно меряет угловую скорость (среднее по фазе).
- Мотор встал → **дебаунс** (N подряд «нет детекта») → **завершение цикла**:
  запись 24-байт записи во Flash + `CMD_CYCLE_PUSH` по кабелю (если есть).
- После записи → обратно в ПРОВЕРКУ (idleChecks=0).

### 2.5. Гироскоп-троттл перехода Пассивный→Активный (12.07.2026)

**Проблема.** Гироскоп — самый дорогой узел (combo HP ~550 мкА), а accel Wake-Up
в поле может дёргаться на постоянную паразитную вибрацию (дорога, стыки). Без
защиты каждое ложное пробуждение крутило бы гироскоп (прогрев 400 мс + CONFIRM)
→ «гироскоп-шторм», ток.

**Решение (accel слушаем всегда, гироскоп троттлим).** accel Wake-Up остаётся
живым в Пассивном (дёшево, ~7 мкА). Вход в Активный (гироскоп-проверку) из
глубокого сна разрешаем **не чаще раза в `gyroRecheckSec`**:
- проснулись по accel-INT → сравниваем прошедшее время (календарь RTC, 1 с) с
  `gyroRecheckSec`. Рано → **дешёвое пробуждение назад в Пассивный** (гироскоп не
  трогаем). Пора → входим в Активный (гироскоп + CONFIRM);
- **эскалация:** целая ПРОВЕРКА-сессия без вращения (idleChecks достиг порога) →
  `gyroRecheckSec` удваивается до потолка (1→2→4→8→16 с). На упорной вибрации без
  вращения гироскоп-пульсы редеют → ток ограничен;
- **сброс в MIN:** при подтверждённом вращении и после завершения цикла («свежие
  уши» на следующую активность).

**Важно — где НЕ троттлим:**
- **фазу ПРОВЕРКА (RTC-опросы) НЕ троттлим** — именно они добирают маргинальный
  низкооборотный старт за пару опросов; троттл только на пробуждениях из
  ГЛУБОКОГО сна (accel-INT);
- эскалируем на «сессию без вращения», а НЕ на каждый промах CONFIRM — иначе
  маргинальный низкооборотный старт наказывался бы задержкой и срезал цикл.

**Цена.** При старте из тишины задержки почти нет (elapsed велик → проверка
сразу, ≈ прогрев 0.4 с). Эскалированный интервал стоит потерей до `gyroRecheckSec`
начала цикла ТОЛЬКО если вращение начинается прямо внутри непрерывной вибрации
(полевой сценарий) — принято как допустимое (наработка в часах, разовые секунды
на старте несущественны).

Параметры: `GYRO_RECHECK_MIN_SEC` = 1, `GYRO_RECHECK_MAX_SEC` = 16 (`Data.h`).

### 2.4. Соответствие фаз и PWR-режимов STM32L4 (глубокий сон = Stop2)

| Фаза (Пассивный/Активный) | PWR-режим | Ток | ОЗУ | Пробуждение |
|---|---|---|---|---|
| ГЛУБОКИЙ СОН (Пассивный) | **Stop2 + EXTI13** | **~7 мкА** (accel 26 LP + MCU <1.3 мкА) | сохраняется | accel-INT (EXTI13) |
| ПРОВЕРКА (Активный) | **Stop2 + RTC** | 1.28 мкА (MCU) + гироскоп-импульсы | сохраняется | RTC ~2 c |
| ВРАЩЕНИЕ / СЕРВИС | Run / любой | — | — | на связи |

**Ток глубокого сна определяется акселерометром** (~7 мкА @26 LP), MCU в Stop2
(<1.3 мкА) на его фоне почти не виден. Именно поэтому Standby-ярус (0.28 мкА)
даёт <15% и **не делается** (см. §2.1) — глубокий сон одноярусный, Stop2.

⚠ **Статус:** глубокий сон = Stop2 + EXTI13, ODR accel 26 Гц LP — реализовано и
подтверждено на стенде. Дальнейшее снижение тока датчика (1.6 Гц) — только после
полевой валидации; системный quiescent — вторичен. См. также раздел «Сон» в
корневом `CLAUDE.md` и `session_notes_2026-07-12_accel_current_odr.md`.

## 3. Контроль кабеля (сервисное окно)

Поверх фаз — гейт по **уровню WKUP1** (кабель подключён = WKUP1 высокий):

| | Кабеля НЕТ (поле) | Кабель ЕСТЬ (стенд/сервис) |
|---|---|---|
| Порог ухода в глубокий сон | `IDLE_CHECKS_TO_DEEP` = 3 (~6 c) | `IDLE_CHECKS_TO_DEEP_CABLE` = 15 (~30 c) |
| Смысл | быстрый глубокий сон → автономность | долгое «сервисное окно» в ПРОВЕРКЕ |
| Достижимость по LTP | только в короткие CONFIRM-окна | ~80% времени (Flash-scan, стоп доходят) |

Логика: полевое устройство сервисят/останавливают ТОЛЬКО подключением кабеля
для снятия данных (иначе смысла отключаться нет — живёт до разряда батареи).
Поэтому с кабелем устройство надолго остаётся на связи (после пробуждения ~30 c
в ПРОВЕРКЕ — успевают и полное сканирование Flash, и `CMD_STOP_REGISTER`).
Глубокий сон при этом ВХОДИТ и с кабелем — просто после ~30 c тишины (на стенде
проверяется паузой длиннее окна).

## 4. Ключевые принципы

- **Пробуждение по фазе, а не постоянный опрос.** В покое — глубокий сон
  (движение), в активности — RTC. Постоянного таймера в покое НЕТ.
- **Старт цикла = момент ПОДТВЕРЖДЕНИЯ вращения (CONFIRM), для обоих режимов**
  (решение 12.07 вечер). Раньше «Работа» метила старт по ПРОБУЖДЕНИЮ («нет
  мёртвого времени»), но это резервировало прогрев+CONFIRM как «вращение» →
  **+1 с** на верхах (квантование). Теперь «Работа» = «Тест»: старт по CONFIRM →
  верхи **ровно 0 с** (как эталон), а на низах — **честная −задержка** (слабая
  вибрация реально подтверждается позже прогрева/опросов; это правда, а не
  артефакт). Реализация: `com.c` REG_STATE_CONFIRM метит старт всегда (не только
  при `testNoSleep`), перетирая пре-штамп `main.c`.
- **EXTI13 армится ИСКЛЮЧИТЕЛЬНО в глубоком сне** (мотор стоит) → нет спина.
- **`Poll_Sensor` ждёт DRDY ГИРОСКОПА** (не accel) → ODR акселерометра на
  измерение не влияет, его свободно опускаем ради тока (104 LP).

## 5. Измерение скорости

- Угловая скорость — **модуль вектора гироскопа** √(x²+y²+z²) (устойчив к
  ориентации оси, в т.ч. вертикальной на стенде); **среднее** по установившейся
  фазе (без стартового пика, без хвоста дебаунса), округление.
- Стоп цикла = момент ПОСЛЕДНЕГО детекта вращения (`lastRotStamp`) — хвост
  дебаунса в длительность не входит.
- Остаточная погрешность — **устоявшийся масштаб гироскопа** (допуск усиления),
  снимается **калибровочным коэффициентом** `SPEED_CALIB_COEF`. ⚠ Коэффициент
  **температурозависим** (gain MEMS-гироскопа плывёт с T) → сейчас НЕЙТРАЛЬ
  (1.0, честный сырой сдвиг), полноценная калибровка — с температурной
  компенсацией (TMP117), в мастере вкладки «Калибровка» (см.
  `session_notes_2026-07-11_speed_avg_axis_fix.md` §10).

## 7. «Работа» (0x1D) vs «Тест» (0x23)

| | «Работа» | «Тест» |
|---|---|---|
| Сон | ДА (3-уровневый автомат + троттл) | НЕТ (бодрый, ловит WUF2 на ходу) |
| Назначение | автономный полевой режим | кабельная проверка/отладка |
| На связи | только в бодрых фазах | всегда |
| Детект/запись/пуш | ОБЩИЕ с «Тестом» | ОБЩИЕ с «Работой» |
| Старт цикла (метка времени) | момент CONFIRM (как «Тест», с 12.07 вечера) | момент CONFIRM |
| Интервал на стенде | ровно 0 с на верхах, честная −задержка на низах | **ровно 0 c (ЭТАЛОН)** |
| Стоп | `CMD_STOP_REGISTER` (0x22) | `CMD_STOP_REGISTER` (0x22) |
| ODR accel | 26 Гц LP (сон) | 104 Гц LP (детект на ходу) |

**«Тест» — эталон точности времени** (подтверждено 12.07 на 100–175 об/мин:
интервал и «Общее» = 0 c без накопления). Использовать «Тест» как референс для
сверки «Работы» и для калибровки скорости (там видна сырая −% гироскопа без
временных артефактов). Разброс ±1 с «Работы» — от старт-по-пробуждению (§4),
в пределах алгоритма.

## 8. Реализация по файлам (прошивка LOGLSMA)

- `App/Inc/Data.h` — поля автомата (`deepSleep`, `idleChecks`, `rotWarmup`,
  `lastRotStamp`, `avgRate`, …), поля троттла (`gyroRecheckSec`,
  `gyroCheckPending`, `lastGyroCheck`), пороги/константы (`GYRO_RECHECK_*_SEC`),
  `SPEED_CALIB_COEF`.
- `App/Src/com.c` — `cmdStartRegister` (старт в глубоком сне, ODR accel 26 LP,
  WK_THS, init троттла), `RotationStateStep` (CONFIRM/ROTATING, idleChecks/
  deepSleep, гейт кабеля, эскалация `gyroRecheckSec` на idle-сессию, сброс на
  вращении), `RotationFinishCycle` (сброс троттла), `PushCycleRecord`.
- `App/Src/Data.c` — `Poll_Sensor` (DRDY гироскопа, модуль вектора),
  `HandleSensorData` (среднее, коэффициент), `SaveParamOnEEPROM` (запись).
- `Core/Src/main.c` — sleep-ветка (deep? EXTI13 : RTC), пробуждение, **троттл-
  гейт гироскопа** (только на deep-wake: рано → назад в Пассивный; пора →
  прогрев + CONFIRM), старт цикла по моменту пробуждения.
- `Core/Src/stm32l4xx_it.c` — `RTC_WKUP_IRQHandler`, `EXTI15_10_IRQHandler`.
