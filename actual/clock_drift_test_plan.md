# План теста дрейфа часов (RTC) — инструкция для ручного прогона

> Составлено 18.07.2026 (вечер). Повод: за ~4 ч после синхронизации часы
> регистратора ушли на **+3 c** (≈ +200 ppm) — это ~10× хуже нормы LSE-кварца
> (±20–30 ppm ≈ ±0.1 c/час). Надо понять, ГДЕ набегают секунды.
> Прошивка для теста: **A ≥ 26.07.18 23:11** (перевод часов в цикле безопасен).

## Что разделяем

Три подозреваемых, каждый тест исключает по одному:

| # | Подозреваемый | Какой тест ловит |
|---|---|---|
| 1 | Кварц LSE / обвязка / календарь сам по себе | Тест 1 (покой) |
| 2 | Сны/пробуждения «Работы» (RTC-wakeup, Stop2) | Тест 2 (Работа без мотора) |
| 3 | Активные циклы (гироскоп, запись, пуши) | Тест 3 (Работа с мотором) |

## Общие правила

- Время меряем по паре «текущее / регистратор» на «Данных» (или на «Стенде»).
- Перед КАЖДЫМ тестом: нажать ⌚ и убедиться, что оба времени зелёные и
  совпадают (±1 c).
- Во время теста НЕ переводить часы ПК (NTP-синхронизацию Windows на время
  теста лучше не трогать — она меняет опору).
- Чем длиннее интервал, тем точнее: минимум 1 час, лучше 2–3 ч (на 200 ppm
  за час набегает ~0.7 c, за 3 ч ~2.2 c — уверенно видно).
- Записывать в таблицу внизу: время ПК и время регистратора на старте и
  финише (по секундам, с одного взгляда/скриншота).

## Тест 1 — «Покой» (кварц/календарь)

1. ⌚ синхронизировать. Записать пару ПК/рег (T0).
2. Оставить устройство В СЕРВИСЕ (ничего не запускать, кабель подключён,
   LOGLSMW открыт). Мотор не крутить, не стучать.
3. Через 1–3 часа записать пару (T1). Дрейф = (рег−ПК)@T1 − (рег−ПК)@T0.

**Интерпретация:**
- |дрейф| ≤ ~0.2 c/час → кварц и календарь здоровы → виноваты сны → Тест 2.
- дрейф ≈ +0.7 c/час (как наблюдалось) → дело в самом кварце/обвязке.
  Лечение штатное: RTC smooth-calibration (RTC_CALR, до ±487 ppm) — по
  calibration_spec_v1.md; постоянный член можно выставить прямо по результату
  этого теста, GPS-PPS не обязателен для первого приближения.

## Тест 2 — «Работа без мотора» (сны/пробуждения)

Только если Тест 1 дал ~0.

1. ⌚ синхронизировать. Записать пару (T0).
2. «Стенд» → кнопка «Работа» (0x1D), мотор НЕ запускать. Устройство уйдёт в
   Пассив (RTC-страховка будит каждые ~25 c — то, что проверяем).
   Экранное время регистратора ЗАМРЁТ — это норма (опросы в «Работе»
   отключены), смотреть нечего до конца теста.
3. Через 1–3 часа: «Стоп» (если не доходит — крутануть мотор и «Стоп» в
   бодрой фазе, либо тумблер). Дождаться оживления времени, записать пару (T1).

**Интерпретация:**
- Дрейф появился только здесь → секунды вносят пробуждения/RTC-wakeup —
  это БАГ прошивки (кандидат: взаимодействие SetWakeUpTimer/Stop2 с
  календарём), чинится в коде — прислать цифры, буду копать.
- Дрейфа нет и здесь → виноваты активные циклы → Тест 3.

## Тест 3 — «Работа с мотором» (полный цикл, опционально)

1. ⌚, записать (T0).
2. «Работа» + длинная циклограмма (например «Случайно ±», часы прогона).
3. По завершении «Стоп», записать (T1) + сохранить журнал стенда (txt).

Дрейф здесь при чистых Тестах 1–2 → секунды съедают активные фазы
(гироскоп/запись/пуши) — тоже код, но другой участок.

## Точность метода (важно, 18.07 23:35)

- **Установка**: с W ≥ 26.07.18 23:35 ⌚ шлёт время ПО ГРАНИЦЕ СЕКУНДЫ ПК —
  погрешность установки упала с ~1 c до ~мс. Использовать эту версию.
- **Чтение**: сравнение целосекундное → джиттер до ±1 c на каждой точке.
  Приёмы: (а) снимать показания в момент СМЕНЫ секунды регистратора (поймать
  переход на экране — квантование падает до ~0.2 c); (б) длиннее интервал:
  при подозреваемых 200 ppm за 8 ч (ночь) набегает ~5.8 c — шум ±1 c уже
  не мешает выводу. Для Теста 1 рекомендуется НОЧНОЙ прогон.

## Примечания

- Тесты можно гонять в любые свободные окна (обед/ночь), друг за другом.
- Знак дрейфа важен: наблюдался ПЛЮС (регистратор спешит).
- Если дрейф в Тесте 1 большой, Тесты 2–3 можно не делать — сразу RTC_CALR.
- Часы после потери питания идут с нуля (маркер BKP_DR0) — если во время
  теста дёрнулось питание, тест недействителен, начать заново.
