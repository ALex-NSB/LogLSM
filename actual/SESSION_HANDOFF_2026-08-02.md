### 1.1. Поколение часов / точки стыка (готово, спец `clock_epoch_seam_spec_v1.md`)
- `EVT_CLOCKZERO` (0xF2) в журнале iflash — инкремент СТРОГО при обнулении
  часов (отсутствие маркёра `0xBEBE` в `RTC_BKP_DR0`), НЕ по каждому reset
  (в отличие от `EVT_POWERLOSS`). Разведено: щелчок питанием на стенде растит

- В запись цикла `rec[40..41]` = **u16 поколение часов** (`iflash_journal_count(EVT_CLOCKZERO)`).
  Смена номера между записями = точка стыка (время рестартовало).
- Файлы: `rtc.c` (флаг `g_clockZeroed`), `main.c` (`g_clockZeroed`,
  `ServiceStorageBootLog` пишет EVT_CLOCKZERO), `iflash.h/.c` (EVT_CLOCKZERO +
  ensure_ready), `Data.c` (`rec[40..41]`).
- В LOGLSMW декодер точек стыка на графиках «Данные» (вертикальные жёлтые
  пунктирные линии) + в тексте «Стенд»/«Память» — БЫЛ в W до отката; см. §3.

## 2. ГЛАВНОЕ ПРОЕКТНОЕ РЕШЕНИЕ СЕССИИ: активация = журнал во внутренней Flash

Долгое обсуждение (снизу вверх), итог зафиксирован. **Реализовать в следующей сессии.**

### 2.1. Признак активации СЕЙЧАС (проблема)
`ts_activation` живёт в ОЗУ: `static uint32_t s_actts = 0xFFFFFFFF` в `com.c`
(0xFFFFFFFF = не активировано). **Теряется при перезагрузке.** Раньше был на
внутр. Flash стр.121 — убрали, т.к. прерванная запись → битый ECC → hardfault
на КАЖДОМ GET_STATS (читался в горячем пути), не лечится перепрошивкой.

### 2.2. Опасность внутренней Flash STM32L4 (и как обойти)
ECC на каждое 64-битное слово. Ломается при (1) прерывании записи/стирания
питанием на полуслове, (2) повторной записи слова без стирания → чтение
битого слова = ECC-NMI/hardfault. **Обход:**
1. Читать из Flash ОДИН раз на старте → кэш в ОЗУ (`s_actts`); GET_STATS из кэша.
2. Append-only: одно чистое слово в стёртый (0xFF) слот, без переписывания
   (так живёт журнал рестартов 124–127).
3. Писать только под стабильным внешним питанием — а активация/деактивация
   **по определению только в «Сервис», по кабелю, под управляющей программой**,
   значит опасный «батарейка+вибрация» не наступает.
4. Сигнатура/тип в слове → стёртая (0xFF) страница читается как «не активировано».

### 2.3. Раскладка внутренней Flash — ТРИ РАЗДЕЛЬНЫЕ области (согласовано)
| Стр. | Что | Кто стирает |
|---|---|---|
| **122** | Журнал активаций (история «жизней», `ts`) — НОВОЕ | «Очистить журналы» |
| **123** (`IFLASH_CFG_PAGE`) | Заводские данные: паспорт (серийник, вариант, дата), калибровки, конфиг | НИКОГДА журнал-очисткой; только паспорт-команда по «шеф»-паролю |
| **124–127** (`IFLASH_JRN_PAGE0`, 4 стр.) | Журнал рестартов (EVT_POWERLOSS/WATCHDOG/CLOCKZERO) | «Сброс WDT» (только это) + «Очистить журналы» |

**Журналы (операционная история) и заводские данные (личность прибора) — в
разных местах, стираются разными командами.** Личность (стр.123) переживает
и стирание NOR, и очистку журналов, и активации.

### 2.4. Модель «жизней» и состояний
- **Активация = граница жизненного цикла**: «Сохранить» (шаг Archive волны
  читает+сохраняет данные прошлой жизни) → стирание → новый `ts` → новая жизнь.
- **Деактивации как отдельной операции НЕТ.** Журнал накапливает ТОЛЬКО
  активации. «Активировано» = есть ≥1 запись; `s_actts` = ts последней.
- Слот активации: `[0]=EVT_ACTIVATION(0xF3)`, `[2..5]=ts` (unix, LE).
  (0xF3 — свободен в пространстве типов iflash; не путать с NOR-маркёром 0xF3.)
- **Состояние = (активировано? по ts) × (несохранённые данные? по флагу):**
  1. Не активировано (журнал пуст) → политика **спрашивает**.
  2. Активировано + флаг снят = **«между жизнями»** → тишина, ходим по сервису
     свободно, ничего не сохраняем, пока не нажмём «Активировать» или прибор
     не запишет новые циклы.
  3. Активировано + флаг взведён → политика **принудительно сохраняет**.
- Навязчивость уходит: принудительное сохранение только когда флаг РЕАЛЬНО
  взведён; «между жизнями» — молчание.

### 2.5. Команда «Очистить журналы» (= настоящая «деактивация»/provision)
- Стирает стр.122 (активации) + стр.124–127 (рестарты) → «не активировано»,
  счётчики 0. **Заводскую стр.123 НЕ трогает** (серийник/калибровки целы).
- Сервис-only, с подтверждением. Отдельно от повседневного «Сброс WDT»
  (тот чистит только 124–127).

### 3.3. Индикаторы ленты активации — доведение (было частично в 16.20–16.60,
но именно тут уехала скобка; накладывать аккуратно):
- **Цветовое правило:** одиночный клик → ЖЁЛТЫЙ (Active); КРАСНЫЙ = тревога
  (рестарты>0 / часы разошлись / несохранённые); ЗЕЛЁНЫЙ — ТОЛЬКО после полной
  волны ▶ (её шаг Done красит сегменты 1..5 + сегмент 0 через updateSaveSegment
  при `m_act.step==Done`).
- **Живой индикатор в ОБОИХ режимах, сразу по состоянию** (не только сервис):
  WDT (GET_STATS): рестарты>0 → красный, иначе жёлтый; Синхро (GET_DATETIME):
  часы разошлись/недостоверны → красный, в допуске → жёлтый. Гейт: не вмешиваться
  во время активной волны (`m_act.step` — шаг волны), т.е. работать при Idle/Done/Error.
- ⚠ ВАЖНО: `ActivationBar::mousePressEvent` (activationbar.cpp:68) ИГНОРИРУЕТ клик
  по сегменту в состоянии **Disabled** (серый). Поэтому сегмент, который надо
  кликать, ОБЯЗАН быть не-Disabled (его «оживляет» живой индикатор). Именно из-за
  этого «Синхро» не кликалась, пока не завели ей живой индикатор.
- **Синхро время (клик):** слать SET_DATETIME **напрямую** (requestCmd + singleShot
  по границе секунды), НЕ через `ui->btnSyncTime->click()` — клик по кнопке
  проходит только если она включена (после автосохранения кнопки временно
  отключены → синхро молчала). Резолв сегмента — на КОНТРОЛЬНОМ чтении
  (`tag==TagSyncTime`), чтобы фоновый GET_DATETIME (~1 Гц) не съедал pending.
- **Режимное правило:** в ОПЕРАТОРЕ кликаются только «Сохранить» (0) и активация
  (▶); «Сброс WDT» (1) и «Синхро время» (2) — только в «Сервис» (гейт в
  `onActivationSectorClicked`). Но КРАСНАЯ ТРЕВОГА (рестарт/рассинхрон) должна быть
  видна и в операторе (индикатор красит в обоих режимах; клик всё равно блокирован).
